## المسار أ — التشغيل والتحرير من أي جهاز (GitHub Codespaces)

**الفكرة:** بيئة تطوير كاملة داخل المتصفّح مبنية من المستودع. لا تنصيب على أي جهاز.

**الخطوات:**
1. على صفحة المستودع: **Code ▸ Codespaces ▸ Create codespace on main**.
2. في الطرفية: `bash brain/bootstrap.sh` (تثبيت تلقائي للحزم والمتصفح).
3. التشغيل الفعلي: `bash brain/tools/final_gate.sh <التاريخ>`.

**ما يعمل:** التحرير · بناء الموقع · توليد PDF وWord · البوابات · فحص المصادر.
**ما لا يعمل:** التسليم على تلغرام (يحتاج التوكن كـCodespaces Secret) · نشر الموقع على منصة Manus (مرتبط بالمشروع هنا) · الجدولة (لا مهمة مجدولة).

**الجهد:** نحو 15 دقيقة. **الملاءمة:** تشغيل يدوي وتحقيق وتطوير، لا تشغيل يومي مستقل.

---

## المسار ب — تشغيل يومي سحابي بلا أي جهاز (GitHub Actions)

**الفكرة:** المهمة اليومية تعمل على سحابة GitHub بالـcron، فتستقل عن Manus في التنفيذ.

**الخطوات:**
1. إضافة سير عمل `.github/workflows/daily.yml`:
   - `on.schedule` عند `40 3 * * *` (03:40 UTC = 06:40 البحرين) + `workflow_dispatch` للتشغيل اليدوي.
   - `runs-on: ubuntu-latest`.
   - الخطوات: `apt-get install libreoffice poppler-utils fonts-hosny-amiri fonts-noto-core` ← `pip install -r brain/requirements.txt` ← `playwright install chromium` ← `bash brain/bootstrap.sh --verify-only` ← `bash brain/tools/final_gate.sh "$(date -u +%F)"`.
2. الأسرار في **Settings ▸ Secrets ▸ Actions**: `TELEGRAM_BOT_TOKEN` · `TELEGRAM_OWNER_CHAT_ID` · `TELEGRAM_WEBHOOK_SECRET` · `DATABASE_URL` (إن لزم) · مفاتيح النماذج عند الحاجة.
3. حفظ المخرجات: رفع `site/dist/` كـartifact، و/أو دفع الإصدار الجديد إلى المستودع.
4. **التسليم على تلغرام يعمل بالكامل** من Actions.

**الكلفة:** دقائق Actions على المستودعات الخاصة (الخطة المجانية تمنح 2000 دقيقة شهريًا؛ مهمة يومية ~12–15 دقيقة ≈ 400 دقيقة شهريًا) — داخل الحد.

**القيد الوحيد:** **نشر الموقع** لا يمكن استدعاؤه من GitHub لأن النشر مرتبط بمشروع الموقع على منصة Manus. الحلول ثلاثة:
- (ب-1) إبقاء النشر يدويًا على Manus بعد مراجعة مخرجات Actions.
- (ب-2) نقل استضافة الموقع إلى مستضيف خارجي (المسار ج).
- (ب-3) تشغيل مهمة Manus مجدولة تقرأ مخرجات Actions وتنشرها (ربط بين المنصتين).

## المسار ج — نقل استضافة الموقع (عند الاستقلال الكامل)

**تنبيه أمني قبل أي نقل:** مواقع **GitHub Pages متاحة للعامة** حتى من مستودع خاص، وهذا يخالف اعتبار المحتوى الحساس. البديل الآمن: مستضيف يدعم التحكم بالوصول.

| المستضيف | التحكم بالوصول | الملاحظات |
|---|---|---|
| Manus (الحالي) | نطاق مُدار من المنصة | الأبسط والأكثر تحكمًا، ويبقى الخيار الموصى به |
| Cloudflare Pages | حماية بـCloudflare Access (قائمة بريد مسموح) | يدعم نشرًا آليًا من GitHub |
| Netlify | كلمات مرور/هوية للموقع | نشر آلي سهل |
| GitHub Pages | لا تحكم — **عام** | غير مناسب للمحتوى الحساس |

**الخطوات عند التنفيذ:** نقل `site/dist/` إلى المستضيف ← ربط النطاق ← تحديث `SITE_ORIGIN` وروابط تلغرام ← اختبار عبور الصفحات والتغذية (`feed.xml`) ← تحديث `appendices/telegram-delivery.md` و`SETUP.md`.

## قائمة تحقق التنفيذ (عند طلب الاستقلال)

1. تأكيد أن نسخة المستودع محدَّثة و`final_gate.sh` ينجح محليًا.
2. اختيار المسار (ب أو ج) وتحديد من يُنفّذ النشر.
3. إضافة الأسرار في الجهة الجديدة (GitHub Secrets أو المستضيف).
4. إنشاء أول تشغيل يدوي (`workflow_dispatch`) والتحقق من: بناء الصفحة · PDF · تسليم تلغرام · فهرس الملفات.
5. مقارنة مخرجات السحابة بمخرجات Manus **يومًا واحدًا على الأقل** قبل إيقاف أي مسار.
6. توثيق نتيجة الانتقال في `audit/سجل-الأعطال-والثغرات.md` وتسجيل الدروس في `memory/learning-log.jsonl`.
7. إبقاء نسخة Manus عاملة أسبوعًا كخط رجوع، ثم تقرير الاستمرار.

- أي تعديل على مولّد الصفحة يتطلب إعادة تجميد الشكل المعتمد، وإلا رفضت بوابة الشكل التسليم.
