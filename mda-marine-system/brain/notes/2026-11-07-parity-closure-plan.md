# إصلاح حالة التماثل الملتزمة وسجل النطاق — خطة تنفيذ 2026-11-07

## الهدف
إصلاح بوابة التماثل بنيويًا بحيث تقارن النسخة الملتزمة من المصدر بالمرآة، وتذكر العمل غير الملتزم معلوماتيًا بلا منع، وتشتق كل تصنيف ونطاق من `runbook/parity-scope.json` مع بقاء الفشل المغلق صارمًا.

## المعمارية
- يقرأ المدقق سجل نطاق معلنًا يحوي أربع فئات: `governing` (حاكم مانع)، `evidence_measurements` (أدلة وقياسات معلوماتية)، `operational_logs` (سجلات تشغيل معلوماتية)، و`generated` (مولّد معلوماتي). لكل فئة سبب مكتوب وسياسة.
- يبني المدقق مسحًا كاملًا للشجرة للإبلاغ، ثم يحدد «اللقطة الملتزمة» عبر Git المصدر (أو مرآة Git كخط أساس تشغيل الخادم غير المربوط بـGit). الملفات الجديدة/المعدلة غير الملتزمة لا تدخل قائمة المنع، لكنها تُطبع باسمها وعددها.
- أي سجل نطاق مفقود/فاسد، أو مسار لا تطاله فئة، أو ملف حاكم ملتزم مفقود/مختلف في المرآة، يخرج فشلًا مغلقًا. تبقى دلالتا `strict` و`advisory` كما هما.

## الملفات المتأثرة
- تعديل: `validators/check_backup_parity.py` — تحميل سجل النطاق، التحقق من الشكل، تصنيف المسارات، واختيار اللقطة الملتزمة.
- إنشاء: `runbook/parity-scope.json` — السجل الحاكم للفئات والأسباب والسياسات.
- تعديل: `tests/test_parity_scope.py` — اختبار عقد السجل والفئات وعدم وجود نطاق مبعثر.
- إنشاء: `tests/test_parity_committed_state.py` — الحالات الأربع المطلوبة واختبار RED/GREEN.
- تعديل: `memory/learning-log.jsonl` — العطل والدرس والحاجز بمعرّف فريد.
- تحديث متزامن: نسخة المصدر في `/home/ubuntu/brain-marine-news` ونسخة Git تحت `mda-marine-system/brain`.

## معايير قبول قابلة للقياس
1. القياس القبلي الخام محفوظ مع `RC` وبصمة؛ الفروقات الحالية تُطابق `git status`/`git ls-files` بوصفها غير ملتزمة.
2. اختبارات `test_parity_committed_state.py` تفشل قبل التعديل للسبب المتوقع، ثم تمر بعده: موجب حاكم مفقود، سالب ملف جديد غير ملتزم، سجل غائب/فاسد، ومسار غير مصنف.
3. `runbook/parity-scope.json` صالح، وكل فئة تحوي سببًا وسياسة، ولا يعتمد المدقق على قائمة مسارات فئوية متناثرة.
4. `python3 validators/check_backup_parity.py --mode strict` يخرج `RC=0` بعد مزامنة المحتوى الحاكم والالتزام؛ لا يتحقق الصفر بحذف ملفات أو بتجاهل عام.
5. لا يتغير عقد `--mode` أو مواضع D040/D070؛ تُقاس مواضع الاستدعاء قبل/بعد.
6. تُشغّل الفحوص المطلوبة و`python3 tools/runbook.py verify` و`G067` و`D040`/`D070` مع حفظ المخرجات والبصمات؛ أي بند غير منفذ يُذكر باسمه وسببه.
7. الدفع يكون إلى فرع غير `main`، ثم طلب دمج ودمج عادي فقط؛ تُحفظ معرفات الفرع والالتزام وPR وmerge commit و`origin/main`.

## أثر الرجوع
يمكن عكس الالتزام الذري الذي يضيف السجل والمنطق والاختبارات والدرس؛ لا توجد استثناءات عامة أو حذف ملفات أو تعطيل بوابة، وتبقى الفئات صريحة وقابلة للمراجعة.
