# تأليف بوابات الفحص وربطها

ألف بوابة قابلة لإعادة التشغيل، واربطها بمشغّل الفحوص، وأثبت أنها تمنع المخالفة فعلًا. القاعدة الحاكمة: **البوابة التي لا تفشل مغلقًا ليست بوابة.**

## حدود المهارة والإحالات

- أحِل قواعد إغلاق الأعطال، سجل الدروس، الأدلة الحية، والحواجز إلى `fault-closure-ops`؛ لا تعِد تعريف سجل الأعطال أو آلية اشتقاق الحالة هنا.
- عند فحص مواضع الأقسام بين المتن والإضافات والتقرير وPDF، اقرأ `report-surface-policy-ops` واتبع سياسته بدل نسخ قائمة الأسطح.
- عند فحص الألفاظ أو تغطية الأسطح اللغوية، أحِل إلى `vocabulary-guard-ops` بدل بناء سجل مفردات موازٍ.
- استخدم `references/gate-checklist.md` قبل الاعتماد، والقوالب من `templates/`، وأدوات `scripts/` فقط بعد قراءة مدخلاتها ومخرجاتها.

## المسار الإلزامي

1. **اقرأ الواقع.** اقرأ البوابة أو البوابات القريبة، `tests/run_checks.sh`، ومصدر البيانات الذي ستقيسه قراءةً فقط. حدّد المدخلات المطلوبة وما يعنيه القياس الصحيح.
2. **عرّف العقد.** ثبّت واجهة `argparse` ذات الخيارات `--date` و`--brain` و`--site` و`--pdf` و`--json`. اجعل كل مدخل مطلوبًا للقياس قابلًا للتحقق؛ لا تجعل قيمة افتراضية تخفي غيابه.
3. **ولّد نقطة البداية.** شغّل:
   ```bash
   python3 scripts/scaffold_gate.py \
     --name <اسم-البوابة> --description "ما تمنعه" \
     --scope "نطاق القياس" --output-dir <نسخة-عمل-مؤقتة>
   ```
   يكتب السكربت `validators/check_<slug>.py` و`tests/test_<slug>.py` في مجلد الإخراج، ولا يستبدل الملفات إلا مع `--force`.
4. **أكمل قاعدة المجال.** أبقِ دالة `violations()` نقية وقابلة للاستيراد والاختبار. استخدم مساعد القراءة، واعتبر الملف المفقود أو الفارغ أو غير القابل للقراءة أو القياس مخالفةً مانعة. اكتب سبب المنع حرفيًا، لا تحوّله إلى تحذير.
5. **أثبت الحالات الثلاث.** شغّل الاختبار المولّد وعدّله ليغطي: مدخلًا سليمًا يجتاز، مدخلًا مخالفًا يُمنع، ومدخلًا مفقودًا أو غير قابل للقياس يُمنع فشلًا مغلقًا. يجب أن يطبع `نجح N · فشل 0` وأن يخرج بصفر عند نجاح الاختبار.
6. **قِس مخرجًا حقيقيًا.** شغّل البوابة على مخرج مبني فعليًا، لا على نسخة مصطنعة فقط، وسجّل الأمر ورمز الخروج والسبب. إذا لم يوجد مخرج قابل للقياس، امنع التشغيل ولا تستنتج النجاح.
7. **اربط بالمشغّل.** استخدم الوضع الافتراضي الجاف أولًا:
   ```bash
   python3 scripts/wire_into_runner.py \
     --runner /path/to/tests/run_checks.sh \
     --gate /path/to/validators/check_<slug>.py \
     --label "وصف الفحص"
   ```
   راجع الفرق، ثم أعد الأمر مع `--apply`. يستخدم السطر دالة `t` وعدّادي `PASS/FAIL` الموجودين في المشغّل، ويرفض التكرار.
8. **أعد القياس والاعتماد.** شغّل البوابة والاختبار والمشغّل، ثم نفّذ قائمة التحقق و`quick_validate.py`. لا تقل «مطابق» قبل وجود دليل تشغيل حي ورمز خروج.

## عقد البوابة

- اجعل `main()` يطبع `مطابق` عند الخروج `0`، أو `منع` مع كل سبب حرفي عند الخروج `2`.
- لا تبتلع الاستثناء أو الخطأ في القراءة. حوّل تعذّر القياس إلى مخالفة مانعة؛ لا تجعل `except` يعيد نجاحًا صامتًا.
- اجعل `--json` يخرج حالة البوابة وقائمة المخالفات دون إسقاط السبب. لا تستخدم JSON لتجاوز الحكم النصي.
- لا تغيّر عدّاد المشغّل ولا تضف مسارًا موازيًا؛ أدرج أمرًا واحدًا عبر دالة العداد الموجودة.
- اجعل الإدراج idempotent: إعادة تشغيل `wire_into_runner.py` لا تضيف سطرًا ثانيًا.

## آلية التعلم الذاتي بعد كل استخدام

بعد كل فشل، مرور كاذب، أو ملاحظة من المالك:

1. سجّل درسًا في `memory/learning-log.jsonl` بصيغة JSONL، بسجل واحد كامل الحقول:
   ```json
   {"ts":"2026-10-28T22:00:00Z","entry_kind":"gate","cls":"<صنف العطل>","status":"open","symptom":"<ما ظهر>","cause":"<السبب الجذري>","fix":"<الإصلاح>، و<الدليل>","barrier":"<الحالة الاختبارية التي ستمنع التكرار>"}
   ```
   لا تنشئ سجلًا ناقصًا أو نصًا وصفيًا بلا أمر ورمز خروج.
2. اقترح تشديدًا على البوابة نفسها: حالة اختبار سلبية جديدة تستهدف العطل، لا مجرد تعليق أو تحذير.
3. أدرج الحالة في اختبار البوابة، ثم تحقّق أن الاختبار يفشل قبل التشديد ويمر بعده، وأنه يطبع `نجح N · فشل 0`.
4. أعد تشغيل البوابة على المخرج الحقيقي والمشغّل، وطابق معرف العطل والدرس والحاجز. لأحكام الإغلاق والسجل التفصيلي استخدم `fault-closure-ops`.
5. امنع التكرار: لا تعلن الإغلاق إذا لم يثبت الحاجز في الاختبار ولم يظهر الدليل الحي. إذا أعطت البوابة نتيجة كاذبة، سجّل العطل والدرس فورًا وشدّد القاعدة بدل تخفيفها.

## مخرجات التسليم

سلّم مسار `SKILL.md`، ومسارات القوالب والسكربتات، ومخرجات التشغيل الفعلية، ونتيجة `quick_validate.py`. اذكر صراحةً أي مسار أو حالة لم تُختبر بعبارة «لم أختبره». لا تنشئ `README.md` أو `CHANGELOG.md` داخل المهارة؛ الموارد المرفقة هي:

- `templates/gate_template.py` — قالب بوابة مع `argparse` و`read_text_file()` و`violations()` و`main()`.
- `templates/test_template.py` — اختبار سلبي/إيجابي قابل للتوليد والاستيراد.
- `scripts/scaffold_gate.py` — توليد البوابة والاختبار من القالبين.
- `scripts/wire_into_runner.py` — إدراج أمر واحد في المشغّل مع فرق جاف ومنع التكرار.
- `references/gate-checklist.md` — قائمة الاعتماد النهائية.
- `references/evidence.md` — سجل الأدلة الناتج من التشغيل الفعلي؛ اقرأه عند مراجعة هذه النسخة.
