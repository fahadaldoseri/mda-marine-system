# تدقيق الآثار الجانبية وواجهة الأداة

## متى تُستدعى

استدعِ هذه المهارة قبل اعتماد أداة جديدة في الكتيب أو البوابة، أو عند ملاحظة كتابة غير معلنة، أو عند رمز خروج غير صفري غير مفهوم، أو عندما ينفّذ `--help` عملًا. لا تستدعها لتشغيل جولة كاملة أو للنشر.

هذه المهارة تملك **الأثر الجانبي والواجهة والفرز**. أحِل عقد الوسائط، النسخ المكررة، والمخرج الحرفي إلى [tool-contract-check-ops](../tool-contract-check-ops/SKILL.md)، وأحِل جرد التغطية إلى [skill-coverage-audit-ops](../skill-coverage-audit-ops/SKILL.md)، وحلقة الإغلاق والتعلم إلى [self-learning-loop-ops](../self-learning-loop-ops/SKILL.md).

## المسار الإلزامي

نفّذ الخطوات بالترتيب، وسجّل الأمر والمخرج ورمز الخروج لكل خطوة:

1. **اقرأ الشيفرة ساكنًا.** حدّد نقطة الدخول، `argparse` أو `sys.argv` اليدوي، الوسائط المطلوبة والاختيارية، ومسارات الكتابة: `write_text`/`write_bytes`/`open(..., w|a|x|+)`/`mkdir`/`rename`/`replace`/الحذف/النسخ، وأي كتابة غير مباشرة إلى سجل أو قاعدة. لا تشغّل الأداة في هذه الخطوة. شغّل `scripts/audit_tool_side_effects.py /path/to/tool.py`؛ فهو يقرأ AST فقط.
2. **قِس قبل التشغيل.** خزّن `mtime` وحجم وبصمة `sha256` للملفات المرشحة، وسجّل لقطة `find` للملفات التي ستظهر بعد نقطة القياس. استخدم مسارًا مؤقتًا أو نسخة معزولة إذا كان الفحص قد يضطر إلى تشغيل أداة غير مضمونة.
3. **شغّل القراءة فقط.** استخدم خيار `--dry-run` أو `--check` أو `--plan` أو ما يعادله بعد إثباته من الشيفرة. إن لم توجد وضعية قراءة فقط، فلا تشغّل الأداة على شجرة المشروع؛ أعلن أن الاختبار محجوب، ولا تستبدل ذلك بالتخمين.
4. **اختبر الواجهة بأمان.** اختبر `--help` ثم وسيطًا غير معروف في بيئة معزولة أو على أداة ثبت ساكنًا أنها لا تكتب قبل تحليل الوسائط. يجب أن يطبع `--help` الاستعمال ويخرج `0` بلا تنفيذ، ويجب أن يخرج الوسيط غير المعروف `2` بلا تنفيذ. طابق المخرج الحرفي مع العقد؛ لا تعتبر الرمز وحده دليلًا.
5. **صنّف كل رمز غير صفري.** استخدم الشيفرة والمخرج معًا:
   - **فشل مغلق مقصود:** فرع صريح يرفض شرطًا معروفًا، بلا traceback، برسالة تشرح المنع؛ مثال `check_run_completeness.py` الذي يعيد `2` عند غياب العلامة أو عدم الإفصاح.
   - **خطأ في الأداة/الاستدعاء:** عقد مكسور، وسيط غير معروف/ناقص، أو واجهة لا تتعامل مع `--help` كما يجب؛ راجع العقد عبر المهارة المحال إليها قبل الحكم.
   - **عطل حقيقي:** استدعاء صحيح ومدخلات متوقعة، ثم استثناء غير معالج أو نتيجة خاطئة أو كتابة غير معلنة أو تغيّر غير مبرر.
   أوقف التسليم عند التصنيف الملتبس، ولا تحوّل عطلًا حقيقيًا إلى «تحذير» لإمرار البوابة.
6. **طبّق الإصلاح الأقل تدخلًا.** أصلح مصدر الأثر: اجعل الكتابة خلف خيار صريح مثل `--apply`، واجعل الوضع الافتراضي قراءة فقط، واجعل `--help` يخرج قبل أي عمل، وارفض الوسائط المجهولة عبر محلّل الواجهة. لا تضعف فحصًا مانعًا ولا تعدّل أدوات النشر أو التلغرام أو النسخ الاحتياطي في جولة التدقيق.
7. **أعد القياس وأثبت قبل/بعد.** أعد `mtime` و`find -newer` و`sha256`، وقارن المحتوى لا البايتات فقط: أثبت أن ملفات القراءة لم تتغير، وأن أي ملف أُنشئ أو عُدّل متوقع ومعلن. أعد اختبار `--help` والوسيط غير المعروف، ثم احفظ الدليل الخام قبل إعلان الاعتماد.

## قواعد حاكمة

- لا تُخفِ فشلًا حقيقيًا بإضعاف فحص أو بتحويل `return 2` إلى `return 0`.
- لا تجعل الكتابة ضمنية؛ لا تكتب إلا خلف خيار صريح موثّق، ويفضّل أن يكون `--apply` أو ما يعادله.
- اجعل `--help` يطبع الاستعمال ويخرج `0` قبل الشبكة والملفات والكتابة. اجعل الوسيط غير المعروف يخرج `2` بلا تنفيذ.
- لا تلمس أدوات النشر أو التلغرام أو النسخ الاحتياطي في جولات الفحص. افحصها ساكنًا فقط، أو استخدم نسخة معزولة مصرحًا بها.
- لا تعتبر وجود `argparse` وحده إثباتًا لسلامة `--help`؛ افحص الكتابة قبل `parse_args` ومسار الاستدعاء.
- لا تعتبر رمز الخروج تصنيفًا بذاته؛ اقرأ الفرع الذي ولّده والمخرج الحرفي.

## أخطاء شائعة يجب إيقافها

- كتابة موجز أو JSON أو سجل داخل المشروع بلا خيار `--apply` أو إعلان مسبق.
- أداة تنفّذ عملًا عند `--help` بسبب كتابة على مستوى الاستيراد أو قبل `parse_args`.
- الخلط بين فشل مغلق مقصود في بوابة وبين عطل في الأداة نفسها.
- مقارنة الملفات بالبايتات فقط دون قراءة المحتوى، أو فحص ملف واحد وإهمال الملفات الجديدة التي يكشفها `find -newer`.
- تشغيل `--help` على أداة `sys.argv` يدوية ثم إعلان السلامة من دون دليل.
- تشغيل أداة نشر/إرسال/نسخ احتياطي «للتجربة» داخل شجرة المشروع.

## التعلم الذاتي والإغلاق

عند اكتشاف أي عطل أو كتابة غير معلنة، سجّله في `audit/سجل-الأعطال-والثغرات.md` بصيغة الأعمدة الاثني عشر الحاكمة، واربطه بسجل الدروس ومصفوفة التتبع، ثم شغّل حارس الإغلاق المملوك للمشروع. لا تعلن الإغلاق بلا سبب جذري، أمر ومخرج قبل/بعد، وتشديد آلي مثبت. عند تكرار الخطأ، شدّد البوابة وحدّث هذه المهارة أو سكربتها، وسجّل التغيير في حلقة التعلم؛ لا تكتفِ بتحديث النثر.

## السكربت المرفق

شغّل:

```bash
python3 /home/ubuntu/skills/side-effects-interface-audit-ops/scripts/audit_tool_side_effects.py /path/to/tool.py
```

يطبع السكربت استخدام `argparse` و`sys.argv`، عمليات ومسارات الكتابة، وحكمًا ساكنًا على سلامة `--help`. لا يشغّل الأداة المفحوصة ولا يستوردها. يعيد رمزًا غير صفري إذا وجد كتابة غير محروسة بخيار صريح؛ اعتبر ذلك مانع اعتماد حتى يثبت الإصلاح. لا يغني هذا السكربت عن تشغيل القراءة فقط أو عن [tool-contract-check-ops](../tool-contract-check-ops/SKILL.md) لقراءة عقد الخروج والمخرج الحرفي.
