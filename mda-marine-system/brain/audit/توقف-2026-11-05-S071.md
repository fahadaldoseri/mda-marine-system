## السبب الجذري
ملف `cumulative-2026/no-material.json` يعلن ثمانية أيام بأنها «بلا مادة»، بينما ملفاتها اليومية في `cumulative-2026/daily/` تحتوي الآن وقائع فعلية نتيجة دفعة الملء الرجعي من أرشيف UKMTO الرسمي:

| اليوم | عدد الصفوف في ملفه اليومي |
|---|---:|
| 2026-04-14 | 1 |
| 2026-06-13 | 1 |
| 2026-07-26 | 1 |
| 2026-08-01 | 2 |
| 2026-08-05 | 3 |
| 2026-08-18 | 3 |
| 2026-08-27 | 1 |
| 2026-09-13 | 1 |

الحارس `validators/check_ledger_continuity.py` يفشل مغلقًا عند تقاطع قائمة `no_material` مع الأيام التي صار لها مادة (`conflicts = material & exempt`)، وهذا تعارض بيانات داخلي لا عطل في التقرير نفسه.

## الأثر
- لم يُنشر أي شيء، ولم يُرسل تلغرام، ولم تُنشأ نسخة احتياطية — التزامًا بأمر المالك عند رمز الخروج 2.
- الخطوات المكتملة في هذه الجولة: W010 (التقرير العربي) · W020 (ملف الواجهة) · W030 (دفتر اليوم) · S070 (دمج الذاكرة التراكمية) — كلها نجحت قبل التوقف.

## الإصلاح الجذري المقترح (بأمر المالك)
حذف الأيام الثمانية من قائمة `no_material` لأنها صارت ذات مادة موثّقة، مع إبقاء الحارس فعّالًا:

```bash
cd /home/ubuntu/brain-marine-news
python3 - <<'PY'
import json, pathlib
p = pathlib.Path('cumulative-2026/no-material.json')
d = json.loads(p.read_text(encoding='utf-8'))
drop = {"2026-04-14","2026-06-13","2026-07-26","2026-08-01","2026-08-05","2026-08-18","2026-08-27","2026-09-13"}
before = len(d["no_material"])
d["no_material"] = [x for x in d["no_material"] if x not in drop]
p.write_text(json.dumps(d, ensure_ascii=False, indent=1) + "\n", encoding='utf-8')
print(f"   قائمة no_material: {before} ← {len(d['no_material'])}")
PY
python3 validators/check_ledger_continuity.py --date 2026-11-05; echo "   rc=$?"
python3 tools/runbook.py run --date 2026-11-05
```
البديل الأكثر تشددًا: إبقاء الأيام في القائمة وحذف صفوفها — وهو مرفوض لأنه يُسقط وقائع رسمية موثّقة من أرشيف UKMTO.
