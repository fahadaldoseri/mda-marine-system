# دليل تشغيل النشر والتحقق الحي

## التسلسل غير القابل للتجاوز

1. ابنِ `dist/` وفحّصه محليًا.
2. شغّل بوابات المحتوى والسطوح والطباعة.
3. اعرض ملخصًا يطلب **قرار نشر صريحًا**؛ لا تعتبر اكتمال البناء إذنًا.
4. بعد القرار فقط نفّذ `git add` ثم `git commit` ثم `git fetch` و`git push` في مستودع الموقع.
5. نفّذ عملية النشر من أداة استضافة Manus أو واجهتها الموثقة. لا تجعل `check_live.sh` يستدعي النشر.
6. شغّل `check_live.sh --compare --date YYYY-MM-DD`.
7. عند الفشل اقرأ سجل `logs/live-YYYY-MM-DD.json`، صنّف السبب، أصلحه في المصدر، ثم قرر إعادة النشر يدويًا. لا تكتب «تم» من رمز HTTP فقط.

## مصفوفة الإثبات

| السطح | المسار الحي | الملف المحلي المقارن |
|---|---|---|
| الرئيسية | `/` | `dist/index.html` |
| صفحة التقرير | `/reports/YYYY-MM-DD.html` | `dist/reports/YYYY-MM-DD.html` |
| الإضافات | `/additions.html` | `dist/additions.html` |
| المصادر | `/sources.html` | `dist/sources.html` |
| التغذية | `/feed.xml` | `dist/feed.xml` |
| اللوحة | `/reports/monthly-2026-10.html` | `dist/reports/monthly-2026-10.html` |
| السجل | `/reports/cumulative-2026.html` | `dist/reports/cumulative-2026.html` |

يستخدم السكربت `curl` بدل Python لأن بعض حمايات الاستضافة ترفض عميل Python. يسجل كل مسار رمز HTTP وحجم الجسم وبصمة SHA-256 محلية وحيّة، ويسجل زمن المحاولة والزمن الكلي وعدد المحاولات. إثبات الإصدار الجديد هو وجود التاريخ المطلوب في جسم صفحة التقرير، ومع `--compare` تطابق البصمة.

## إعادة المحاولة والتشخيص

القيم الافتراضية ست محاولات وفاصل 45 ثانية. اضبطها للاختبار فقط عبر `LIVE_RETRIES` و`LIVE_RETRY_SECONDS` أو الوسيطين المقابلين. لا تجعل إعادة المحاولة تنفذ commit أو push أو publish. رمز `2` يعني أن التحقق لم يثبت النجاح.
