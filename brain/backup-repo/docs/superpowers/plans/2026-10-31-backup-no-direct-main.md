# Backup No Direct Main Implementation Plan

> **For agentic workers:** تُنفَّذ الخطوات بالتتابع مع اختبار RED ثم GREEN، ولا يُدفع أي شيء إلى `main` مباشرة.

**Goal:** منع `brain/tools/github_backup.sh` منعًا بنيويًا وتشغيليًا من الدفع إلى `main`، وتحويله إلى فرع + طلب دمج، مع حاجز واختبار سالب/موجب ودليل تشغيل حي.

**Architecture:** يبقى `main` مصدر الشيفرة، ويُبنى الالتزام الاحتياطي على فرع قصير العمر باسم `backup/<date>-<timestamp>`. يدفع السكربت الفرع فقط ثم ينشئ طلب دمج عبر `gh`; غياب `gh` أو فشل الدفع/الطلب يسجل فشلًا مغلقًا ويمنع أي تراجع إلى `main`. يفحص `check_backup_push_safety.py` السكربت قبل أي دفع ويمنع أي صيغة `git push` تستهدف `main`.

**Tech Stack:** Bash، Python 3، unittest، Git، GitHub CLI.

**Spec:** طلب المالك 2026-10-31 لإغلاق ك-398.

## Global Constraints

- ممنوع الدفع المباشر إلى `main` أو `force-push` أو إعادة كتابة التاريخ.
- ممنوع استخدام أدوات الطباعة/PDF أو تفعيل `print.enabled` أو إرسال Telegram.
- الفشل في إنشاء الفرع أو دفعه أو إنشاء PR فشل مغلق ومسجل في سجل النسخ الاحتياطي.
- كل ادعاء إغلاق يثبت بأمر حديث ومخرج خام وبصمة ورمز خروج.
