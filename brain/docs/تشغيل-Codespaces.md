# التشغيل من أي جهاز عبر GitHub Codespaces

**الغرض:** فتح النظام وتشغيله كاملًا على بيئة سحابية من أي جهاز في العالم — بلا تثبيت محلي، وبلا مساحة عمل Manus، وبلا معرفة مسبقة بالمسارات. البيئة تُبنى من المستودع نفسه، وتُطفأ عند عدم الحاجة.

| الملف | وظيفته |
|---|---|
| `.devcontainer/devcontainer.json` | يحدّد صورة البيئة ومواصفاتها ويشغّل التهيئة تلقائيًا |
| `brain/bootstrap.sh` | يثبّت حزم النظام (LibreOffice · poppler · خطوط عربية) وحزم بايثون ومتصفح Chromium |
| `brain/tools/verify_codespace.sh` | **إثبات وظيفي بأمر واحد**: تصريف · بوابات · بناء · PDF · Word |

> **مقيس فعليًا:** جُرّبت السلسلة في بيئة معزولة تحاكي Codespaces (استنساخ نظيف + بيئة بايثون فارغة): تثبيت المتطلبات ✔ · تصريف كل الملفات ✔ · بناء 17 صفحة إصدار ✔ · **توليد PDF المعتمد مع نجاح بوابة الشكل** (1.0 م.ب) ✔ · **نسخة Word طبق الأصل** (14/14 قسمًا) ✔.

---

## 1. الخطوات خطوة بخطوة

### أ) إنشاء البيئة (مرّة واحدة، 5–8 دقائق)

1. افتح المستودع `mda-marine-system` على GitHub (خاص بحسابك).
2. الزر الأخضر **Code** ← تبويب **Codespaces** ← **Create codespace on main**.
3. اختر نوع الجهاز **2 cores · 8 GB RAM** (كافٍ ومقتصد؛ الحد الأدنى مطلوب في الإعدادات هو هذا).
4. انتظر انتهاء التهيئة التلقائية: ستُثبَّت LibreOffice وpoppler والخطوط العربية ومتصفح Chromium وحزم بايثون. راقب الطرفية أسفل الشاشة.

### ب) إثبات أن البيئة صالحة (دقيقة واحدة)

```bash
bash brain/tools/verify_codespace.sh
```

يجب أن تنتهي النتيجة بـ:

```
  نجح: N · تحذير: M · فشل مانع: 0
  ✔ البيئة صالحة لتشغيل النظام كاملًا (بناء · PDF · Word · البوابات).
```

- **`فشل مانع: 0`** = البيئة جاهزة، ويمكن الاعتماد على مخرجاتها.
- أي سطر يبدأ بـ `✘` يذكر سببه في السجل المفصّل الذي يطبعه السكربت في آخر سطر.

### ج) فحص المتطلبات وحده (عند الشك)

```bash
bash brain/bootstrap.sh --verify-only     # يفحص بلا تثبيت أي شيء
bash brain/bootstrap.sh                   # إعادة التثبيت الكامل عند نقص
```

## 2. الأوامر الجاهزة داخل البيئة

```bash
# بناء الموقع كاملًا من البيانات (الإصدارات + اللوحة + السجل + التغذية)
python3 site/generator/build_site.py

# توليد PDF الشكل المعتمد ليوم محدد + صورة الخريطة
python3 brain/tools/export_report_assets.py --date 2026-10-19

# نسخة Word طبق الأصل من PDF المعتمد
python3 brain/tools/build_report_docx_exact.py --date 2026-10-19

# بوابة التسليم النهائية على إصدار يوم (فشل مغلق)
bash brain/tools/final_gate.sh 2026-10-19

# الخط اليومي الكامل ليوم جديد
bash brain/tools/daily_pipeline.sh 2026-10-20

# معاينة الموقع محليًا (منفذ 3000 مُهيَّأ ومعروض تلقائيًا)
bash brain/tools/ensure_devserver.sh 3000

# تحقّق وظيفي كامل من البيئة
bash brain/tools/verify_codespace.sh
```

المخرجات تُكتب داخل `site/dist/reports/` (الصفحات و`pdf/` و`img/`) و`brain/reports/docx/` — تُنزَّل من مستكشف الملفات في المحرّر بالنقر عليها بزر الفأرة الأيمن ← Download.

## 3. الأسرار والقنوات

- **لا سر واحد في المستودع** (محروس ببوابة `check_backup_parity.py` التي تفشل عند أي تسرّب).
- رمز بوت تلغرام يُقرأ من متغيّر البيئة `TELEGRAM_BOT_TOKEN`، والأدوات تقرأ `brain/.env` تلقائيًا عند غيابه:

```bash
printf 'TELEGRAM_BOT_TOKEN=%s\n' '<الرمز من BotFather>' > brain/.env
chmod 600 brain/.env
```

- معرّف المحادثة في `brain/appendices/telegram-chat.json` (منقّح في المستودع بوسم `[محجوب]`؛ ضع قيمتك الحقيقية محليًا عند الحاجة).
- كلمة سر الويب هوك (`brain/state/webhook-secret.txt`) مستثناة من المستودع بحكم التصميم.

## 4. ما يعمل في البيئة وما لا يعمل

| العمل | في Codespaces |
|---|---|
| بناء الموقع · PDF المعتمد · Word · كل البوابات · الخط اليومي · إرسال تلغرام (بالرمز) | ✔ يعمل كاملًا |
| تعديل القواعد والأدوات والتقارير ثم الرفع إلى GitHub | ✔ |
| **نشر الموقع على المنصة** | ✘ لا — النشر خطوة على Manus وحدها |
| **خدمة الويب هوك لبوت تلغرام** | ✘ لا — تعمل على خدمة Manus المنشورة |
| **المهام المجدولة (06:40 و07:00 بتوقيت البحرين)** | ✘ لا — الجدولة على Manus |

الخلاصة: Codespaces بيئة **تشغيل وتحرير واختبار** عند الحاجة، وليست بديلًا عن الجدولة والنشر.

## 5. عند ظهور مشكلة — الحالات الأربع الأرجح

| العَرَض | السبب | الحل |
|---|---|---|
| `✘ لا خط عربي` أو مربعات في PDF | حزمة الخطوط لم تُثبَّت | `sudo apt-get install -y fonts-hosny-amiri fonts-noto-core fontconfig && fc-cache -f` |
| `✘ متصفح Playwright غير مثبّت` | لم يُنزَّل Chromium أو نقصت مكتباته | `python3 -m playwright install chromium --with-deps` |
| `error: externally-managed-environment` عند pip | بيئة بايثون محميّة | `python3 -m venv .venv && . .venv/bin/activate && pip install -r brain/requirements.txt` |
| `✘ soffice غير مثبّت` | LibreOffice مفقود (يحتاجه Word) | `sudo apt-get install -y libreoffice` |

وملاحظة تشغيلية: **توليد PDF يحتاج إنترنت** لأن خطوط الواجهة تُحمَّل من Google Fonts — وهذا يجعل شكل الصفحة واحدًا على كل الأجهزة. عند الحاجة إلى استقلال تام عن الشبكة، تُجمَّع الخطوط داخل `site/assets/fonts/` ويُغيَّر مرجع الخطوط محليًا.

## 6. اقتصاد التشغيل

- البيئة تُحسب بالساعات: أوقفها من قائمة **Codespaces** ← **Stop**، واحذفها (**Delete**) إذا لم تعد تحتاجها.
- العمل النصّي الصغير يكفيه التحرير المباشر على GitHub بلا تشغيل ورشة.
- الحد الشهري للساعات يختلف بحسب الحساب — راجع صفحة الاستخدام في GitHub.

---

## 7. قائمة تحقق سريعة قبل الاعتماد على أي بيئة جديدة

1. `bash brain/bootstrap.sh --verify-only` — المتطلبات كلها `✔`.
2. `bash brain/tools/verify_codespace.sh` — `فشل مانع: 0`.
3. `python3 brain/validators/check_backup_parity.py --mode strict` — **مطابق** (في الشجرة المحلية، لا داخل المستنسخ).
4. راجع أن مخرجات PDF وWord تحمل الشكل المعتمد نفسه: عدد الصفحات وترقيمها وبطاقة القرار في الصفحة الأولى.
