## ٢) طرائق التفكير والقواعد الذهبية

1. **لا إصلاح بلا قياس:** كل ادّعاء إصلاح يُقاس (تدقيق آلي + تدقيق حي بالمتصفح + مقارنة بصرية) ويُطابق ما بينهما.
2. **الفشل المغلوق:** البوابات تُرجع رمز خروج مانعًا (2) لا تحذيرًا؛ والخط اليومي لا يُسلِّم عند أي مخالفة.
3. **التحقق على نسخة مستنسخة، لا على الشجرة المحلية** — كشف تناقضًا في النسخة الاحتياطية لم يظهر محليًا.
4. **كل عطل يُسجَّل بسببه الجذري ومانعه** في `audit/سجل-الأعطال-والثغرات.md`، ولا يُغلق قبل تسجيل مانع يمنع تكراره.
5. **فصل المعلومة عن الاحتمال:** مؤكد · مرجّح · ممكن · غير حاسم — وحدود البحث الثلاثة: «لم يُعثر على… في المصادر المفحوصة» (حدّ بحث) · «غير محسوم» (تعارض) · «لم يُثبت» (نفي السند).
6. **الأصل قبل النقل:** كل بلاغ رسمي يُحفظ نصًّا في `archive/originals/<التاريخ>/` قبل الاعتماد عليه.
7. **الأسلوب الكتابي للتقارير العملياتية:** جملة ≤ 20 كلمة · «نفّذوا» للتوجيه · بلا حشو منهجي · تعبير زمني بصيغة DTG + توقيت البحرين لا «قبل أيام».
8. **التعداد يُكتب نقاطًا في المصدر من البداية** (بوابة `check_points_rule.py`) — منعًا لعرض النقاط كفقرة محشورة.

## ٣) المكتبات والأدوات

**بايثون (`requirements.txt` — يُثبَّتها `bootstrap.sh` آليًا):**

| المكتبة | الاستخدام |
|---|---|
| `python-docx` | توليد نسخ Word بطبق الأصل من الصفحة المطبوعة (RTL) |
| `playwright` | طباعة PDF من الصفحة + التدقيق الحي والقياس البكسلي |
| `Pillow` | قطع الصفحات وتركيب ألواح المراجعة البصرية وقياس الفراغات |
| `shapely` | حساب مواضع الوقائع على الخريطة التشغيلية |

**حزم النظام:** LibreOffice (`soffice` — تحويلات المستندات) · poppler-utils (`pdftoppm` · `pdftotext` · `pdfinfo` — القياس والتدقيق الطباعي) · خطوط عربية (Amiri · Noto) · متصفح Chromium عبر Playwright.

**واجهات خارجية:** Telegram Bot API (تسليم) · Google Fonts (خطوط الواجهة) · وسيط نصّي `r.jina.ai` لمسار الإرسال البديل · مفاتيح نماذج لغوية (اختيارية: مراجعة لغوية آلية والتكيّف التحليلي).

**البيئة السحابية:** GitHub Codespaces عبر `.devcontainer/devcontainer.json` · GitHub CLI · أدوات المنصة (Webdev للنشر · manus-config للجدولة والموصلات).

## ٧) إجراء إضافة معرفة جديدة (إلزامي)

1. **قاعدة أو أسلوب** → يُكتب في القسم المختص داخل `sections/` ويُربط ببوابة إن كان قابلًا للفحص الآلي.
2. **لفظ ممنوع** → يُضاف إلى `style-blacklist.json` بالأداة `tools/style_learn.py` (مع سبب المنع والبديل)، فيمنعه التسليم تلقائيًا.
3. **مصطلح معتمد** → يُضاف إلى `appendices/terminology.md` ويُنفَّذ الاستبدال عبر `tools/normalize_terms.py`.
4. **درس من عطل** → `memory/record_learning.py` **و**سطر في `audit/سجل-الأعطال-والثغرات.md` بسبب جذري + مانع.
5. **معرفة جديدة من أي تطوير** → تُدفع إلى المستودع الخاص `mda-marine-system` فيفُتح النظام من أي جهاز بآخر إصدار.
