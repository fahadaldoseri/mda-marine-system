# الفحص الآمن لأدوات `sys.argv`

## متى تُستدعى

استدعِ هذه المهارة قبل تشغيل أداة مشروع غير موثقة العقد، أو عند وجود قراءة يدوية لـ`sys.argv`، أو عند الشك في أن `--help` ينفّذ عملًا، أو قبل إدخال أداة في مانيفست أو بوابة. استخدم الجرد الساكن الواقعي في `/home/ubuntu/audit-2026-10-30/static-help-inventory.md` قراءةً فقط؛ فهو يسجل 29 أداة يدوية غير آمنة واجهيًا، ولا يبرر تشغيلها.

أحِل مبادئ الآثار الجانبية العامة إلى [side-effects-interface-audit-ops](../side-effects-interface-audit-ops/SKILL.md)، وعقد الوسائط والمخرج الحرفي ورموز الخروج إلى [tool-contract-check-ops](../tool-contract-check-ops/SKILL.md)، وقرار الملكية والتفرع والدمج إلى [skill-ownership-merge-ops](../skill-ownership-merge-ops/SKILL.md). لا تكرر تلك الملكيات هنا.

## المسار الإلزامي

نفّذ الخطوات بالترتيب، وسجّل الأمر والمخرج الحرفي ورمز الخروج. لا تعدّل شجرة المشروع المفحوصة.

1. **صنّف قبل التشغيل.** اقرأ AST لكل ملف Python، وحدّد نقطة الدخول، ووجود `sys.argv` يدويًا أو `argparse.parse_args`، واستدل على الفئة الأقوى بالترتيب التالي: `تنشر/ترسل/تنسخ`، ثم `تتصل بالشبكة`، ثم `تكتب ملفات`، ثم `قراءة فقط`. اعتبر الفئات الثلاث الأولى غير آمنة للفحص الحي. شغّل `scripts/classify_argv_tools.py PATH` لهذا الجرد فقط؛ فهو لا يستورد ولا يشغّل الأداة.
2. **جهّز أثر القياس.** قبل أي تشغيل، أنشئ marker خارج الشجرة، وخذ قائمة وبصمات `sha256` للملفات، ثم استخدم `find PROJECT -type f -newer MARKER -print` بعد كل تشغيل. استبعد marker وملفات الأدلة من الشجرة المقاسة. اجعل القياس قابلًا لإعادة التشغيل وسجّل وقت البداية.
3. **اختبر الفئة الأولى فقط.** لا تشغّل إلا أداة صنّفها AST قراءةً فقط، واجتازت عقد الواجهة ساكنًا، ولا تحتوي كتابة أو شبكة أو نشرًا ظاهرًا. اختبر بالترتيب: `--help`، ثم `--__argv_probe_unknown__`، ثم التشغيل الافتراضي الآمن أو الوسائط الموثقة التي لا تغيّر الحالة. اجعل `--help` يطبع الاستعمال ويخرج `0`، والمجهول يخرج `2` بلا تنفيذ؛ طابق المخرج مع [tool-contract-check-ops](../tool-contract-check-ops/SKILL.md).
4. **أثبت عدم التغيير بعد كل تشغيل.** قارن `find -newer` والبصمات والمحتوى بعد كل وضع. إذا ظهر ملف جديد أو تغيّر ملف غير معلن، أوقف الجولة فورًا وصنّف الأداة غير آمنة؛ لا تواصل الاختبار ولا تحوّل العطل إلى تحذير.
5. **استدل على الممنوع ساكنًا.** سجّل لكل أداة كتابة/شبكة/نشر أو واجهة `sys.argv` يدوية: `استدلال ساكن لا قياس حي`. لا تستنتج سلامة التنفيذ من AST وحده، ولا تشغّل أداة لا تملك مسار قراءة فقط مثبتًا.
6. **أصلح بأقل تدخل.** انقل تحليل الوسائط قبل أي أثر، واجعل `--help` يخرج قبل العمل، وارفض المجهول برمز `2`، واجعل الكتابة خلف خيار صريح مثل `--apply`، مع إبقاء الأخطاء الحقيقية ورموزها. لا تحذف فحصًا مانعًا ولا تغيّر معنى `return 2` لإمرار البوابة.
7. **أعد الإثبات والثبات.** أعد الأوضاع الثلاثة، والقياس بعد كل وضع، وفحص المخرج الحرفي. كرر الجولة مرة ثانية للتأكد من ثبات النتيجة، ولا تعلن الإصلاح قبل تطابق العقد والبصمات وعدم وجود أثر جديد.
8. **أنشئ جدول النتائج.** اطبع أو احفظ: المسار، الفئة، دليل AST، عقد الواجهة، حالة القياس الحي، رمز كل وضع، وقرار `آمن للفحص` أو `محجوب`. افصل دائمًا بين القياس الحي والاستدلال الساكن.

## الأثر والحدود

استخدم قالبًا مشابهًا للآتي، مع إبقاء marker خارج المشروع:

```bash
marker=$(mktemp /tmp/argv-probe.XXXXXX)
find /home/ubuntu/brain-marine-news -type f -print0 | sort -z | xargs -0 sha256sum > /tmp/argv-before.sha256
python3 TOOL --help; rc=$?
find /home/ubuntu/brain-marine-news -type f -newer "$marker" -print
find /home/ubuntu/brain-marine-news -type f -print0 | sort -z | xargs -0 sha256sum > /tmp/argv-after.sha256
cmp -s /tmp/argv-before.sha256 /tmp/argv-after.sha256 || { echo 'أثر غير متوقع؛ أوقف'; exit 1; }
rm -f "$marker"
exit "$rc"
```

نفّذ الأمر في بيئة معزولة أو نسخة اختبارية عندما تتطلب الأداة مدخلات، ولا تخمّن «التشغيل الافتراضي الآمن». لا تشغّل في جولة الفحص أداة تكتب، أو تتصل بالشبكة، أو تنشر/ترسل/تنسخ؛ اكتفِ بالاستدلال الساكن ووسم النتيجة حرفيًا.

## قواعد حاكمة وأخطاء اليوم

- امنع تشغيل أدوات الكتابة أو النشر أو الاتصال بالشبكة في جولة الفحص.
- لا تُخفِ فشلًا حقيقيًا بإضعاف فحص أو تحويل رمز منع إلى نجاح.
- ميّز في التقرير بين `استدلال ساكن لا قياس حي` وبين القياس الذي نفذ فعلًا.
- اجعل `--help` استعمالًا فقط ويخرج `0`، والمُعطى غير المعروف يخرج `2` بلا تنفيذ.
- أوقف: أداة تنفذ عملًا عند `--help`، أداة تعتبر `--help` مسار ملف، كتابة ضمنية بلا خيار صريح، الخلط بين فشل مغلق مقصود وعطل أداة، واختبار أداة نشر ظنًا أنها قراءة فقط.
- ادفع كل تعديل في فرع مستقل، وشغّل التحقق، ثم اطلب الدمج؛ لا تدفع مباشرة إلى `main`. أحِل تفاصيل الملكية إلى [skill-ownership-merge-ops](../skill-ownership-merge-ops/SKILL.md).
