# التدقيق متعدد الوكلاء بقياس مستقل

هذه المهارة هي **المنسّقة العامة**: توزّع التدقيق، تحفظ عدم تداخل النطاقات، وتجمع نتائج المالكين دون أن تنتزع ملكية أي بوابة محور. طبّق القياس قبل/بعد، مستويات الأدلة، الجولة الثانية، ومنع الادعاء بلا قياس كما هو في [عقد جولة التدقيق المشتركة](references/audit-round-contract.md).

> **خريطة الإحالة:** أمانة المصدر/السجل/المولّد/السطح إلى `report-content-fidelity-ops`؛ قرار نقل القسم وتغطية الأسطح السبعة إلى `report-surface-policy-ops`؛ الحكم المرئي وRTL وPDF والقص وأهداف اللمس والروابط إلى `live-visual-audit-ops`. ما عدا هذه المحاور يبقى عند مالكه المسجّل في المانيفست ولا يُدمج هنا.

استخدم `scripts/claims_table.py` لإنتاج التصنيف الموحّد، و`templates/audit-report.md` للتقرير النهائي.

## توزيع الوكلاء

أنشئ وكيلًا مستقلًا لكل نطاق، ولا تسمح لوكيل أن يعلن سلامة نطاق وكيل آخر

1. **الواجهة**؛ افحص البنية، التخطيط، القص، الاستجابة، والعناصر المرئية.
2. **الطباعة**؛ افحص PDF، عدد الصفحات، بصمة CSS، الخريطة، مفتاحها، التذييل، والانقسامات.
3. **اللغة**؛ افحص العربية، المصطلحات، الأرقام، RTL/LTR، والاتساق التحريري.
4. **الأسطح والروابط**؛ افحص المسارات المنشورة والروابط والأصول وحالات HTTP أو رموز الأدوات.
5. **الوصول**؛ افحص لوحة المفاتيح، التركيز، النص البديل، العناوين، التباين، وأسماء العناصر المساعدة.

اطلب من كل وكيل ملف ادعاءات JSON منفصلًا وفق مخطط `references/claim-measurement.md`، واقرأ [العقد المشترك](references/audit-round-contract.md) قبل بناء الملف.

## دورة التدقيق والإصلاح

1. ثبّت نسخة الإدخال ووقت الجولة، ثم اجمع ملفات الادعاءات من الوكلاء دون دمج دليل أحدهم في نطاق آخر؛ نفّذ بقية دورة القياس والإصلاح والجولة الثانية وفق [العقد المشترك](references/audit-round-contract.md).
2. شغّل جدول الادعاءات:

```bash
python3 /home/ubuntu/skills/multi-agent-audit-ops/scripts/claims_table.py /path/to/claims.json
```

اعتمد تصنيف العقد المشترك ومخرج الجدول، وأوقف التقرير عند المخالفة المغلقة بدل تحويل الادعاء إلى نجاح.

3. سجّل للمالك المختص فقط العيوب التي صنّفها القياس؛ أبقِ دليل كل محور منفصلًا، ولا تغلق غير المتحقق.
4. استخرج أصناف الثغرات واقتراحات التشديد

```bash
python3 /home/ubuntu/skills/multi-agent-audit-ops/scripts/propose_tightening.py \
  --root /path/to/brain --log /path/to/brain/audit/faults-raw.jsonl \
  --out /path/to/tightening-proposals.md
```

## ترتيب التقرير

استخدم القالب كما هو، وبالترتيب الإلزامي التالي

1. العيوب المؤكدة.
2. ادعاءات مرفوضة أو مصحّحة.
3. ما ظهر سليمًا.
4. ما لم يُتحقق.
5. خطة الإصلاح بالترتيب.

اربط كل عيب بسجل الأعطال وبقياسه. لا تضع إصلاحًا في الخطة لادعاء لم يثبت عيبه، ولا تضع ادعاءً سليمًا بلا دليل.

## حلقة التحسين الذاتي

نسّق لكل ثغرة سلسلة قابلة للمراجعة وفق العقد المشترك، ثم أحِل السبب الجذري والقاعدة المشددة والاختبار السلبي إلى مالك المحور. اعتبر مخرج `propose_tightening.py` اقتراحًا يحتاج اعتمادًا وتنفيذًا، لا دليل إغلاق. أرفق المخرج مع التقرير، واذكر أي وكيل أو سطح لم يُختبر صراحة.
