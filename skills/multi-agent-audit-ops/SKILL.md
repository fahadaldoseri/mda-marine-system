# التدقيق متعدد الوكلاء بقياس مستقل

وزّع التدقيق على وكلاء ذوي نطاقات غير متداخلة، وحوّل كل ادعاء إلى قياس يمكن إعادة تشغيله، ولا تقبل عبارة «سليم» أو «مؤكد» بلا أمر ورمز خروج أو رقم. استخدم `scripts/claims_table.py` لإنتاج التصنيف الموحّد، و`templates/audit-report.md` للتقرير النهائي.

## توزيع الوكلاء

أنشئ وكيلًا مستقلًا لكل نطاق، ولا تسمح لوكيل أن يعلن سلامة نطاق وكيل آخر

1. **الواجهة**؛ افحص البنية، التخطيط، القص، الاستجابة، والعناصر المرئية.
2. **الطباعة**؛ افحص PDF، عدد الصفحات، بصمة CSS، الخريطة، مفتاحها، التذييل، والانقسامات.
3. **اللغة**؛ افحص العربية، المصطلحات، الأرقام، RTL/LTR، والاتساق التحريري.
4. **الأسطح والروابط**؛ افحص المسارات المنشورة والروابط والأصول وحالات HTTP أو رموز الأدوات.
5. **الوصول**؛ افحص لوحة المفاتيح، التركيز، النص البديل، العناوين، التباين، وأسماء العناصر المساعدة.

اطلب من كل وكيل ملف ادعاءات JSON منفصلًا يضم معرّفًا فريدًا، ونطاقًا، وادعاءً، وأمر القياس، ورمز الخروج أو رقمًا. اقرأ `references/claim-measurement.md` قبل بناء الملف.

## دورة التدقيق والإصلاح

1. ثبّت نسخة الإدخال ووقت الجولة، ثم اجمع ملفات الادعاءات من الوكلاء دون دمج دليل أحدهم في نطاق آخر.
2. حوّل كل ادعاء إلى قياس قابل للتكرار؛ استخدم أمرًا حقيقيًا مثل مدقق أو اختبار أو طلب HTTP، وسجّل رمز الخروج أو الرقم والعتبة.
3. شغّل جدول الادعاءات

```bash
python3 /home/ubuntu/skills/multi-agent-audit-ops/scripts/claims_table.py /path/to/claims.json
```

صنّف كل صف إلى **مؤكد بقياس** أو **مرفوض بقياس** أو **لم يُتحقق**. إذا حمل الصف `confirmed` بلا قياس صالح، أخرج الرمز 2 وأوقف التقرير؛ لا تحول الادعاء إلى نجاح.

4. سجّل في سجل الأعطال العيوب المؤكدة بقياس فقط، مع السبب الجذري، والقاعدة التي تُشدّد، والاختبار السلبي. لا تصلح عيبًا مرفوضًا أو غير متحقق منه بوصفه عيبًا.
5. أصلح العيوب المؤكدة فقط، ثم شغّل الاختبارات السلبية التي تمنع عودتها.
6. نفّذ **جولة تدقيق ثانية** بالقياسات نفسها، وقارن الصفوف والرموز والأرقام. أبقِ ما لم يُتحقق منه في قسمه ولا تغلقه ادعائيًا.
7. استخرج أصناف الثغرات واقتراحات التشديد

```bash
python3 /home/ubuntu/skills/multi-agent-audit-ops/scripts/propose_tightening.py \
  --root /path/to/brain --log /path/to/brain/audit/faults-raw.jsonl \
  --out /path/to/tightening-proposals.md
```

## ترتيب التقرير

استخدم القالب كما هو، وبالترتيب الإلزامي التالي

1. العيوب المؤكدة.
2. ادعاءات مرفوضة أو مصحّحة.
3. ما ظهر سليمًا.
4. ما لم يُتحقق.
5. خطة الإصلاح بالترتيب.

اربط كل عيب بسجل الأعطال وبقياسه. لا تضع إصلاحًا في الخطة لادعاء لم يثبت عيبه، ولا تضع ادعاءً سليمًا بلا دليل.

## حلقة التحسين الذاتي

اجعل كل ثغرة سلسلة واحدة قابلة للمراجعة؛ السبب الجذري ثم القاعدة المشددة ثم الاختبار السلبي ثم جولة التدقيق الثانية. اعتبر مخرج `propose_tightening.py` اقتراحًا يحتاج اعتمادًا وتنفيذًا، لا دليل إغلاق. أرفق المخرج مع التقرير، واذكر أي وكيل أو سطح لم يُختبر صراحة.
