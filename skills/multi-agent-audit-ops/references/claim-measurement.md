# قياس الادعاء والتدقيق متعدد الوكلاء

حوّل كل ادعاء إلى صف مستقل في JSON. استخدم الشكل التالي

```json
{
  "claims": [
    {
      "id": "UI-001",
      "claim": "لا يوجد قص في واجهة التقرير",
      "status": "confirmed",
      "measurement": {
        "command": "python3 validators/check_layout.py --page dist/reports/2026-10-28.html",
        "exit_code": 0
      }
    },
    {
      "id": "P-001",
      "claim": "مفتاح الخريطة كامل في صفحة واحدة",
      "measurement": {
        "command": "python3 validators/check_pdf_format.py --pdf dist/reports/pdf/2026-10-28.pdf",
        "exit_code": 4
      }
    }
  ]
}
```

اعتبر القياس صالحًا فقط إذا احتوى `command` غير فارغ مع `exit_code` رقمي أو رقم قياس. يمكن استخدام `value` مع `expected` و`operator` من `>=` أو `<=` أو `==` أو غيرها. استخرج التصنيف من القياس؛ لا تثق بحقل `status` وحده.

- `exit_code: 0` يعني أن الادعاء اجتاز الاختبار وصنّفه السكربت **مؤكد بقياس**.
- رمز خروج غير صفري يعني فشل القياس وصنّفه **مرفوض بقياس**.
- غياب الأمر أو الرقم، أو وجود نتائج متعارضة، يصنّف **لم يُتحقق**.
- إذا أعلن الصف `confirmed` بلا قياس صالح، اطبع المخالفة وأخرج بالرمز 2 حتى لو لم تُصنّفه الأداة مؤكدًا.

## سجل الجولة

احتفظ لكل ادعاء بمعرّف، ونطاق وكيل واحد، وأمر القياس، ورمز الخروج أو الرقم، ووقت التنفيذ، ونتيجة الجولة. لا تسجل «سليم» أو «مؤكد» دون هذه الحقول.

## دورة الإصلاح

سجّل العيب المؤكد في سجل الأعطال مع السبب الجذري والقاعدة المشددة والاختبار السلبي. أصلح العيوب المؤكدة فقط. لا تصلح ادعاءً مرفوضًا أو غير متحقق منه باعتباره عيبًا. بعد الإصلاح أنشئ جولة تدقيق ثانية بالقياسات نفسها، ثم أضف دليل الجولة الثانية إلى السجل.
