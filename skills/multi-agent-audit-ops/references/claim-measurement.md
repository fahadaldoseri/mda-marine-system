# قياس الادعاء والتدقيق متعدد الوكلاء

هذا الملف يحدد **مخطط JSON** فقط. لبروتوكول القياس قبل/بعد، مستويات الأدلة، منع الادعاء بلا قياس، والجولة الثانية، اقرأ [عقد جولة التدقيق المشتركة](audit-round-contract.md). حوّل كل ادعاء إلى صف مستقل في JSON. استخدم الشكل التالي

```json
{
  "claims": [
    {
      "id": "UI-001",
      "claim": "لا يوجد قص في واجهة التقرير",
      "status": "confirmed",
      "measurement": {
        "command": "python3 validators/check_layout.py --page dist/reports/2026-10-28.html",
        "exit_code": 0
      }
    },
    {
      "id": "P-001",
      "claim": "مفتاح الخريطة كامل في صفحة واحدة",
      "measurement": {
        "command": "python3 validators/check_pdf_format.py --pdf dist/reports/pdf/2026-10-28.pdf",
        "exit_code": 4
      }
    }
  ]
}
```

يجب أن يحتوي `command` على أمر غير فارغ، وأن يحتوي القياس على `exit_code` رقمي أو قيمة رقمية. يمكن استخدام `value` مع `expected` و`operator` من `>=` أو `<=` أو `==` أو غيرها؛ يستخرج `claims_table.py` التصنيف من القياس ولا يثق بحقل `status` وحده.

## حقول التتبع

احتفظ لكل ادعاء بمعرّف، ونطاق وكيل واحد، وادعاء، وأمر القياس، ورمز الخروج أو الرقم، ووقت التنفيذ، ونتيجة الجولة، ومسار المخرج أو اللقطة عند الحاجة. لا تسجل نتيجة نهائية دون الحقول التي يفرضها العقد المشترك.
