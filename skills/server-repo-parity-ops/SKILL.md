# تشغيل تماثل الخادم والمستودع

نفّذ العمل بوصفه عملية تماثل قابلة للإثبات، لا بوصفه نسخ ملفات عشوائيًا. أبقِ `brain` و`site` ومجلد المهارات قابلين للتمرير صراحةً، ولا تعدّل أي ملف قبل أخذ قياس قبلي.

## التسلسل الإلزامي

1. حدّد الجذور الفعلية. مرّر `--brain` و`--site` و`--repo` و`--skills` حيث تدعمها الأدوات، أو عيّن `BRAIN_DIR` و`SITE_DIR` و`BACKUP_REPO_DIR` و`SKILLS_DIR`.
2. قِس قبل التعديل. شغّل مدقق التماثل في الوضع التنبيهي وسجّل أعداد الشجرة المحلية والمستودع والزوائد والانحرافات ورمز الخروج.
3. افحص قابلية النقل. شغّل `check_portable_paths.py` على الجذرين الحقيقيين؛ ارفض أي مسار جذر مكتوب حرفيًا داخل ملف تنفيذي.
4. اختر اتجاهًا واحدًا لكل جولة. لا تخلط الخادم إلى المستودع مع المستودع إلى الخادم في الأمر نفسه.
5. نفّذ نسخة جافة أولًا، ثم نفّذ التغيير بعد مراجعة الخطة.
6. قِس بعد التعديل بالأداة نفسها، ثم راجع بصمات الملفات، وعدّ الملفات المفقودة والزوائد والروابط، ولا تعتبر رمز الخروج وحده دليلًا.
7. ادفع إلى فرع قصير العمر، وافتح طلب دمج، واطلب المراجعة. لا تدفع مباشرة إلى `main` ولا تجعل أداة التشغيل تنفّذ `git push` إلى `main`.

## الاتجاه الأول الخادم إلى المستودع

استخدمه عندما يكون الخادم مصدر التغيير المعتمد:

```bash
python3 scripts/validators/check_backup_parity.py --brain "$BRAIN" --site "$SITE" --repo "$REPO" --skills "$SKILLS" --mode advisory
python3 scripts/tools/sync_to_repo.py --brain "$BRAIN" --repo "$REPO/brain" --dry-run
python3 scripts/tools/sync_to_repo.py --brain "$BRAIN" --repo "$REPO/brain"
python3 scripts/tools/github_backup.py
python3 scripts/validators/check_backup_parity.py --brain "$BRAIN" --site "$SITE" --repo "$REPO" --skills "$SKILLS" --mode strict
```

استخدم `sync_to_repo.py` فقط لمزامنة شجرة الدماغ إلى الوجهة المحددة، واستخدم `github_backup.py` لبناء النسخة النظيفة متعددة الجذور. قبل أي دفع أنشئ فرعًا مثل `sync/server-to-repo-YYYYMMDD`، راجع `git diff` و`git status`، ثم ادفع الفرع وافتح طلب دمج.

## الاتجاه الثاني المستودع إلى الخادم

اعتبر GitHub مصدر الحقيقة للشيفرة والقواعد فقط. نفّذ أولًا خطة جافة:

```bash
python3 scripts/tools/apply_from_github.py --repo "$REPO" --brain "$BRAIN" --site "$SITE" --skills "$SKILLS" --dry-run
```

لا تستخدم `--accept-repo` إلا بعد مراجعة كل تعارض. عند الموافقة شغّل الأمر على فرع مستودع منفصل، واترك الأرشيف الذي تنشئه الأداة، ثم شغّل تحقق المشروع بعد التطبيق. لا تطبق بيانات التشغيل أو ملفات الأسرار بهذه الأداة.

## الاستثناءات ومنع الزوائد

عامل الاستثناء كسياسة مكتوبة لا كاختصار. تستثني القواعد الافتراضية الكاش، `.git`، `__pycache__`، `node_modules`، `shots`، `dist`، `brain-backup`، مجلد الحالة، ملفات البيئة، سر الويب هوك، والمخرجات المولّدة التي يعاد بناؤها. لا توسّع قائمة الاستثناءات دون سبب ومسار واختبار سلبي.

اسمح فقط بالزوائد الموثقة وظيفيًا مثل إعدادات GitHub، فهرس المستودع، الأرشيف الداخلي، اللقطات والمخرجات المولّدة. افحص النوع أيضًا، فالملف الذي صار رابطًا أو الرابط الذي صار ملفًا انحراف. افحص محتوى المستودع بحثًا عن أسماء الأسرار وأنماطها، ولا تنقل قيمة سرية لمجرد أن المسار متطابق.

## القياس والإثبات

سجّل في نتيجة الجولة على الأقل ما يلي

- عدد عناصر الشجرة المحلية بعد الاستثناءات.
- عدد عناصر المستودع المتتبعة فعليًا.
- عدد الزوائد في المستودع، وعدد الملفات المفقودة، وعدد انحرافات المحتوى، وعدد الروابط.
- رمز الخروج قبل الجولة وبعدها، وأمر كل تشغيل.
- بصمة أو قائمة مسارات الانحراف دون إدراج سر أو محتوى حساس.

لا تعلن المطابقة إلا إذا مرّ الفحص الصارم وكان عدد الزوائد غير المسموحة والانحرافات صفرًا. شغّل القياس مرتين متتاليتين عندما تتغير قائمة الاستثناءات أو المخرجات المولّدة.

## حلقة التحسين الذاتي

سجّل كل ثغرة جديدة في سجل الأعطال بسلسلة كاملة

1. اكتب العرض والسبب الجذري، لا العرض وحده.
2. أضف قاعدة تشديد قابلة للتنفيذ، مثل توسيع نطاق المقارنة ديناميكيًا من الملفات المتتبعة أو منع `lstrip` للمسارات أو منع الدفع المباشر إلى `main`.
3. أضف اختبارًا سلبيًا يكسر الحالة عمدًا ويثبت أن الحارس يمنعها.
4. أعد تشغيل الجولة بعد الإصلاح، ثم شغّل أداة الاقتراح:

```bash
python3 scripts/propose_tightening.py --brain "$BRAIN"
```

استخرج الأداة أصناف الثغرات من `audit/faults-index.jsonl` و`audit/faults-raw.jsonl` و`audit/سجل-الأعطال-والثغرات.md`، وتقترح لكل صنف تشديدًا واختبارًا سلبيًا. طبّق المقترحات التي تخص الجولة، وسجّل البقية كقرارات معلّقة بدل إسقاطها.

## الملفات المرفقة

- `scripts/tools/sync_to_repo.py` للمزامنة أحادية الاتجاه مع حذف الزوائد غير المستثناة.
- `scripts/tools/github_backup.py` لبناء نسخة نظيفة وحجب القيم الحساسة ونقل الروابط النسبية.
- `scripts/tools/apply_from_github.py` لتطبيق الشيفرة فقط مع كشف التعارض والأرشفة.
- `scripts/validators/check_backup_parity.py` لقياس الشجرة والمستودع والزوائد والانحراف وتسرب الأسرار.
- `scripts/validators/check_portable_paths.py` لمنع المسارات المطلقة في الشيفرة التنفيذية.
- `scripts/propose_tightening.py` لحلقة التحسين الذاتي.
- `references/parity-runbook.md` لتسلسل الأوامر وسياسة الفرع وطلب الدمج.

## التعلم الذاتي والتحسن (إلزامي)

بعد كل استخدام لهذه المهارة، وبعد كل عطل أو ملاحظة أو نتيجة كاذبة:

1. **سجّل الدرس** فورًا في سجل تعلم المشروع: `memory/learning-log.jsonl` بصيغة JSONL بالحقول
   `ts` · `entry_kind` · `cls` · `status` · `symptom` · `cause` · `fix` · `barrier`
   عبر `server-repo-parity-ops/scripts/propose_tightening.py` (أو أداة تسجيل المشروع إن وُجدت). لا تكتب الدرس في الذاكرة ولا في محادثة فقط.
2. **اقترح تشديدًا** يمنع تكرار العطل: حالة فحص جديدة · اختبار سلبي · حارس في الأداة.
   استخدم `/home/ubuntu/skills/fault-closure-ops/scripts/propose_tightening.py` لصياغة الاقتراح، ثم نفّذه فعلًا.
3. **تحقّق أن الحاجز قائم**: شغّل الفحص أو الاختبار الجديد وأظهر نتيجته (`نجح N · فشل 0`).
   لا تُعلن حاجزًا قبل تشغيله.
4. **امنع التكرار**: قبل الإدراج، افحص هل الإدخال موجود بمعرّف أو بصمة نصية؛ لا تُكرّر إدخالًا.
5. **لا تكتمل الجولة** إن بقيت ملاحظة بلا درس أو درس بلا حاجز مُثبت.
