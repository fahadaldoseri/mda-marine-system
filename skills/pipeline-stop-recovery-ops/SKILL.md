# استئناف الخط المتوقف حتى التسليم

## القاعدة الحاكمة

لا تستأنف قبل أن تعرف **أي خطوة** توقفت و**بأي رمز** و**بأي دليل**. ولا تعلن اكتمالًا قبل مخرج حي من البوابة نفسها.
لا تشغّل كتيبًا موازيًا إن كان هناك تشغيل قائم، ولا تعِد تشغيل خطوة نجحت.

## متى تُستدعى

- `runbook.py status` يُظهر خطوة `failed` أو خطوات `لم تبدأ` بعدها.
- شكوى «لماذا لم يُنشر التقرير؟» أو «التقرير لم يُسلَّم».
- بوابة طباعة/أسطح/لغة/تماثل أوقفت التسليم بعد نجاح المحتوى.
- نشر جرى لكن التحقق الحي فشل (404 أو اختلاف بصمة).

## المسار الإلزامي

1. **لقطة تشخيص حية**: `scripts/stop_triage.sh --date <date>` — تُظهر الخطوة المتوقفة، ذيل سجلها، العمليات الجارية، حالة الروابط الحية، ونتيجة التماثل في نداء واحد. لا تبنِ تشخيصًا على الذاكرة.
2. **تأكيد عدم وجود تشغيل موازٍ**: `pgrep -af 'runbook.py run --date <date>'`. إن وُجد، لا تشغّل ثانيًا.
3. **تصنيف التوقف** حسب جدول الأعطال في `references/playbook.md` (توقف بوابة مخرج · توقف تماثل · توقف تحقق حي · توقف تسليم خارجي).
4. **إصلاح جذري في فرع**: التشخيص أولًا (قياس حي)، ثم إصلاح واحد مبرهن، ثم اختبار الفرع، ثم طلب دمج يُدمج بتفويض المالك. لا دفع مباشر إلى `main`.
5. **استئناف بخطوة واحدة**: `python3 tools/runbook.py run --date <date>`
   - خروج `10` = الخطوة بانتظار الوكيل: نفّذ نصّها وحدها ثم `complete <STEP> --date <date>` ثم أعد `run`.
   - خروج `2` = توقف: ارجع إلى الخطوة 3 بسبب جديد. ممنوع النشر أو الإرسال في هذه الحالة.
6. **النشر والتحقق الحي**: لا تعتبر النشر تمّ بمجرد أن أمر النشر نجح. انتظر ظهور الإصدار فعلًا (قد يتأخر الانتشار دقائق)، ثم أعد خطوة التحقق الحي حتى تنجح، وأثبت مطابقة بصمة الملف الحي للمحلي.
7. **التماثل والتوثيق**: بعد نجاح الخطوات كلها، زامن شجرة الخادم مع المستودع (انظر `server-repo-parity-ops`)، وافحص التماثل، وسجّل كل عطل جديد ودَرسه في سجل الأعطال وسجل التعلم بدليله.

## المصائد المرصودة (التفصيل والأوامر في `references/playbook.md`)

| المصيدة | العَرَض | العلاج |
|---|---|---|
| تأخر الانتشار | النشر رمز 0 ثم فشل التحقق الحي 404 | أعد المحاولة بانتظار متكرر؛ لا تُعدّل شيئًا في التقرير |
| ملفات `.bak` داخل الشجرة | انحراف تماثل يسمّي ملفات جديدة غير متتبَّعة | انقلها خارج الشجرة إلى مجلد تدقيق، ولا تحذفها |
| ملفات مُولَّدة على الخادم | `docs/...` وملفات المهارات تبقى مختلفة رغم نجاح النسخ | زامن الخادم→المستودع قبل بوابة التماثل (`sync_to_repo.py`) |
| مزامنة المسارات | المزامنة تخطّط لحذف آلاف الملفات | اضبط `--repo` على مجلد الهدف الحقيقي داخل المستودع، وتحقّق بـ`--dry-run` أولًا |
| دمج طلب سحب غير تفاعلي | `gh pr merge` بلا رقم يطبع المساعدة | مرّر الرقم: `gh pr merge <N> --repo <owner/repo> --merge` |
| بوابة «توقف ناجحة» | خطوة نفّذها المحرّك ترفض `complete` | لا تكملها يدويًا؛ أعد `run` فقط |

## الأدوات

- `scripts/stop_triage.sh --date <date> [--brain <dir>] [--site <dir>] [--url <origin>]` — لقطة تشخيص للتوقف: حالة الكتيب، الخطوة المتوقفة وذيل سجلها، العمليات الجارية، الروابط الحية، التماثل.

## الحدود

- لا تجاوز خطوة في الكتيب ولا تعلن «لا ينطبق» بلا شرط مكتوب في المانيفست.
- لا إرسال على تلغرام ولا نشر خارج خطوة المانيفست وبلا تفويض صريح من المالك.
- لا تخفيف عتبة بوابة ولا اعتماد بصمة بلا سبب ودليل.
- لا إعادة كتابة تاريخ Git ولا حذف فروع أو نسخ احتياطية.

## المهارات المرتبطة

`runbook-execution-ops` (تنفيذ الكتيب وأكواده) · `print-layout-gate-ops` (بوابات الطباعة والفراغات) ·
`server-repo-parity-ops` (التماثل) · `site-publish-live-verify-ops` (النشر والتحقق الحي) ·
`fault-closure-ops` (تسجيل الأعطال والدروس) · `gate-authoring-ops` (بناء بوابة عند تكرار عطل).
