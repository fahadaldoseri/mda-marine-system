# عمليات التدقيق البصري الحي

## استخدم المهارة عندما

استخدمها قبل تسليم تقرير عربي RTL منشور، أو موقعًا حيًا، أو نسخة PDF، أو عند تحويل ملاحظات وكيل بصري إلى قرارات قابلة للإثبات. استخدمها أيضًا بعد أي إصلاح يمس الطباعة، الفهرس، الجداول، النطاقات الرقمية، الروابط، أو التخطيط المتجاوب.

## المبدأ الحاكم

**لا بند يدخل التقرير النهائي قبل إعادة قياسه.** صنّف كل ملاحظة صراحةً إلى واحدة من ثلاث حالات: `مؤكد` عندما يعيد القياس إنتاجها مع دليل، `مؤكد بالوكيل` عندما قال بها وكيل ولم تُعد القياس بعد، و`مرفوض` عندما لا يعيد القياس إنتاجها. إذا غاب القياس أو اللقطة أو تعذر الحكم، اكتب `لم يتحقق` بدل `سليم`؛ راجع [قائمة الأدلة](references/evidence-checklist.md) و[معيار الشدة](references/severity-rubric.md).

لا تحتج باستخراج `pdftotext` للحكم على اتجاه RTL أو ترتيب الكلمات والأرقام. قد يشوّه استخراج النص العربي اتجاه السطر وترتيبه. افتح معاينة صورة الصفحة للحكم على الاتجاه، ترتيب النطاقات، انقسام الجداول، الفراغات، والقص. استخدم السكربتات النصية كأدلة مساعدة قابلة لإعادة التشغيل، لا كبديل عن المعاينة البصرية.

## سير العمل الإلزامي

1. **ثبّت المدخلات.** سجّل روابط الأسطح، مسار PDF، ملف المصدر، وقت التدقيق، ومجلد المخرجات. لا تعدّل الموقع أو PDF أو المشروع أثناء جولة القياس.
2. **شغّل وكلاء متخصصين بالتوازي وبقراءة فقط.** وزّع العمل على: واجهة بصرية، طباعة/PDF، لغة ومحتوى، وأس surfaces وروابط. اطلب من كل وكيل ملاحظة، شدة أولية، موضعًا، ولقطة أو قياسًا؛ لا تعتبر قوله حكمًا نهائيًا، بل صنّفه `مؤكد بالوكيل`.
3. **نفّذ جولة تحقق مركّزة.** أعد قياس أخطر البنود أولًا: الفهرس والصفحات، النطاقات والنسب، القص، الجداول، أهداف اللمس، والروابط. افتح صور PDF واللقطات، ولا تطبق إصلاحًا خلال هذه الجولة.
4. **وحّد التقرير.** اكتب بندًا واحدًا لكل عطل، مع الشدة، الحالة، المسار/الرابط، رقم الصفحة، مسار اللقطة، القياس الرقمي، الأمر المستخدم، وحدود الدليل. ادمج الملاحظات المتكررة ولا ترفع ملاحظة وكيل غير معاد قياسها إلى `مؤكد`.
5. **اكتب قائمة الإصلاح.** رتّب البنود حسب `مانع` ثم `مهم` ثم `تحذير` ثم `تجميلي`. حدّد المالك وخطوة الإصلاح وحزمة الفحص التي ستمنع التكرار. لا تنشر ولا تدفع ولا تعدّل المشروع من هذه المهارة دون تفويض مستقل.
6. **أعد التدقيق بعد الإصلاح.** أعد تشغيل الفحص نفسه على النسخة المعدّلة، وقارن القياس قبل/بعد، والتقط لقطة جديدة. أغلق البند فقط إذا تغيّر الدليل إلى نتيجة مقبولة؛ وإلا أبقه `لم يتحقق` أو `مؤكد` بحسب القياس الجديد.

## فحوص PDF النصية المساعدة

شغّل الأوامر من مجلد `scripts/` أو استخدم المسارات المطلقة. تعتمد مطابقة العناوين على تطبيع حتمي: أزل التشكيل، وحّد `أ/إ/آ/ٱ → ا`، وحّد `ة → ه`، وحّد `ى → ي`، أزل التطويل وعلامات الاتجاه، وأزل المسافات وعلامات الترقيم للمقارنة. لا تستخدم تشابه الحروف أو التخمين الضبابي. عند عكس مستخرج RTL السطر كاملًا، جرّب الانعكاس الحتمي للنص المطبع فقط، وسجّل ذلك كدليل نصي لا كحكم بصري.

### تحقق فهرس PDF

نفّذ:

```bash
cd /home/ubuntu/skills/live-visual-audit-ops/scripts
python3 verify_pdf_index.py --pdf FILE
```

يقرأ أسطر الفهرس المبكرة ذات العناوين العربية وأرقام الصفحات، ويطابق العنوان المطبع مع ظهوره في صفحات PDF الفيزيائية (الترقيم يبدأ من 1)، ثم يقارن الرقم المتوقع بالصفحة الفعلية. يطبع لكل عنوان `[OK]` أو `[DIFF]` والصفحة وتطابقاتها.

رموز الخروج: `0` عندما تطابق جميع الإدخالات؛ `1` لملف مفقود أو خطأ تشغيل؛ `2` عند وجود اختلاف، أو غياب إدخالات فهرس قابلة للتحقق. لا تعتبر نجاحه دليلًا على اتجاه RTL أو سلامة التخطيط؛ عاين صورة الصفحة.

### تحقق النطاقات والنسب

جهّز ملف مصدر UTF-8 ثم نفّذ:

```bash
cd /home/ubuntu/skills/live-visual-audit-ops/scripts
python3 verify_range_bidi.py --pdf FILE --source SOURCE.txt
```

طبّع الأرقام العربية والفارسية إلى أرقام ASCII، ووحّد الشرطات، واستخرج النطاقات `رقم-رقم` والنسب ذات `%` أو `٪`. قارن التسلسل المتوقع بالقيم المستخرجة. اسمح بإعادة ترتيب القيم التي يسببها مستخرج RTL، لكن علّم عكس طرفي النطاق أو أرقامه أو النسبة كدليل طبقة نصية. اطلب معاينة الصورة دائمًا قبل الحكم النهائي على الاتجاه والترتيب.

رموز الخروج: `0` عندما لا يظهر عكس داخل قيمة نطاق/نسبة (حتى لو أعاد المستخرج ترتيب القيم، مع تحذير المعاينة)؛ `1` لخطأ الإدخال أو التشغيل؛ `2` عند عكس مؤكد في طبقة النص؛ `3` عندما يتعذر محاذاة القيم أو يختلف عددها، ويجب عندها التصريح بعدم الحكم وطلب معاينة بصرية.

## فحص الأسطح الحية

اكتب ملف UTF-8 يحوي رابطًا واحدًا في كل سطر، ثم نفّذ:

```bash
cd /home/ubuntu/skills/live-visual-audit-ops/scripts
python3 audit_live_surfaces.py --urls-file urls.txt --out DIR
```

افتح الروابط بمتصفح Playwright للقراءة فقط، وسجّل العناصر المرئية ذات عرض أو ارتفاع أقل من `44px` ضمن أهداف اللمس، والخلايا/البطاقات التي طول نصها `0`، والعناصر الداخلية ذات `scrollWidth > clientWidth + 4` مع `overflow-x` محصور، والعناصر ذات `scrollHeight > clientHeight + 4` مع `overflow:hidden`. احفظ لقطة كاملة لكل رابط وتقريرًا نصيًا في `DIR`.

رموز الخروج: `0` بلا ملاحظات وبلا أخطاء تحميل؛ `1` لملف روابط فارغ، اعتماد ناقص، أو فشل تحميل جميع الروابط؛ `2` عند وجود ملاحظات قابلة للقياس. افحص التقرير واللقطات حتى عند الرمز `0`، لأن القياسات الآلية لا تثبت جودة RTL البصرية أو دلالة المحتوى.

أضف سجلًا اختياريًا لسجل أعطال/دروس المشروع عبر تمرير مساره:

```bash
python3 audit_live_surfaces.py --urls-file urls.txt --out DIR \
  --log-path PROJECT/logs/live-visual-audit.jsonl
```

يقبل السكربتان الآخران `--log-path` بالطريقة نفسها. اكتب في السجل كل عطل مؤكد أو حالة `لم يتحقق`، مع الأمر، الدليل، والنسخة التي عولجت. اجعل منع التكرار فحصًا آليًا في حزمة الاختبارات أو CI، لا تذكيرًا في نص التقرير.

## حلقة التعلم

مرّر `--log-path` إلى الفحوص التي كشفت العطل، ثم أضف سجل الدرس في المشروع المستهدف: السبب الجذري، القياس الذي أثبته، الإصلاح، فحص المنع، ورابط/مسار اللقطة. سجّل العطل والدرس في سجل واحد JSONL أو في سجلين متفق عليهما، لكن لا تتركهما في ملاحظات محادثة فقط. بعد الإصلاح أعد الأمر نفسه، وأضف نتيجة ما بعد الإصلاح إلى السجل، ثم ثبّت فحصًا آليًا يعيد كشف النمط في كل تشغيل لاحق.

لا تضع في السجل عبارة «تم الإصلاح» بلا قياس قبل/بعد. إذا تعذر فتح رابط أو قراءة PDF، سجّل `لم يتحقق` وسبب التعذر بدل استنتاج السلامة.

## الاختبار المنفّذ لهذه الحزمة

اختُبرت الأدوات على مدخلات اصطناعية صغيرة داخل مجلد اختبار خاص بالحزمة، وليس على تقرير عربي منشور أو موقع خارجي حقيقي:

- شغّل `verify_pdf_index.py --pdf .test/index-ok.pdf`: استخرج 3 إدخالات، طابقها مع الصفحات 2–4، وأعاد `EXIT:0`.
- شغّل `verify_pdf_index.py --pdf .test/index-bad.pdf`: كشف اختلافًا واحدًا (الفهرس 9 مقابل الصفحة الفعلية 2)، وأعاد `EXIT:2`.
- شغّل `verify_range_bidi.py --pdf .test/ranges-ok.pdf --source .test/ranges.txt`: وجد 3 قيم صحيحة مع إعادة ترتيب استخراج RTL وتحذير المعاينة، وأعاد `EXIT:0`.
- شغّل `verify_range_bidi.py --pdf .test/ranges-inverted.pdf --source .test/ranges.txt`: كشف ثلاثة انعكاسات (`12-18`، `25%`، `100-120`)، وأعاد `EXIT:2`.
- شغّل `audit_live_surfaces.py --urls-file .test/urls.txt --out .test/live-log-out`: التقط لقطة، ووجد 5 ملاحظات: هدف لمس `30x30px`، خلية فارغة، بطاقة فارغة، overflow بمقاس `180/120px`، وقص `80/20px`، وأعاد `EXIT:2`.
- مرّر `--log-path` إلى الأدوات الثلاثة؛ كُتبت سجلات JSONL بنجاح، وكتب فحص السطح 5 أسطر للعناصر المقاسة. شغّل أيضًا `python3 -m py_compile` على السكربتات الثلاثة، وكانت النتيجة `PY_COMPILE_OK`.

لم يُختبر ما يلي: تقرير أو PDF منشور حقيقي، موقع HTTPS يتطلب تسجيل دخول أو JavaScript خارجيًا، PDF مشفر أو ممسوح ضوئيًا بلا طبقة نص، أحجام PDF كبيرة، منافذ عرض الهاتف، حدود `44px` نفسها، أو الحكم البشري على صور RTL. التقطت الاختبارات لقطات، لكن لم أزعم أن التقاطها يساوي معاينة بصرية بشرية. نفّذ هذه الحالات في المشروع المستهدف قبل التسليم.

## التعلم الذاتي والتحسن (إلزامي)

بعد كل استخدام لهذه المهارة، وبعد كل عطل أو ملاحظة أو نتيجة كاذبة:

1. **سجّل الدرس** فورًا في سجل تعلم المشروع: `memory/learning-log.jsonl` بصيغة JSONL بالحقول
   `ts` · `entry_kind` · `cls` · `status` · `symptom` · `cause` · `fix` · `barrier`
   عبر `/home/ubuntu/skills/fault-closure-ops/scripts/record_fault.py` (أو أداة تسجيل المشروع إن وُجدت). لا تكتب الدرس في الذاكرة ولا في محادثة فقط.
2. **اقترح تشديدًا** يمنع تكرار العطل: حالة فحص جديدة · اختبار سلبي · حارس في الأداة.
   استخدم `/home/ubuntu/skills/fault-closure-ops/scripts/propose_tightening.py` لصياغة الاقتراح، ثم نفّذه فعلًا.
3. **تحقّق أن الحاجز قائم**: شغّل الفحص أو الاختبار الجديد وأظهر نتيجته (`نجح N · فشل 0`).
   لا تُعلن حاجزًا قبل تشغيله.
4. **امنع التكرار**: قبل الإدراج، افحص هل الإدخال موجود بمعرّف أو بصمة نصية؛ لا تُكرّر إدخالًا.
5. **لا تكتمل الجولة** إن بقيت ملاحظة بلا درس أو درس بلا حاجز مُثبت.
