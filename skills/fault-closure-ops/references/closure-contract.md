# عقد الإغلاق المشترك — Closure Contract

**المالكة:** `fault-closure-ops`  
**النطاق:** سلامة صف العطل وحالة الإغلاق ودليلها، لا دورة التعلم اليومية أو الدفع إلى الفرع.  
**المراجع الحاكمة:** `G048` بوابة الإغلاق، و`Q012` جولة الإغلاق/الفحص؛ تبقى `D050` ضمن ملكية `self-learning-loop-ops`.

هذا هو المصدر الوحيد للعقد البنيوي المشترك بين مهارتي `fault-closure-ops` و`self-learning-loop-ops`. لا تُعاد صياغة قواعده في `SKILL.md` أو في مهارة دورة التعلم؛ تُحال إليه فقط.

## 1) مخطط السجل القياسي — 12 عمودًا

| # | العمود | المعنى |
|---|---|---|
| 0 | المعرّف | `ك-NNN` (ظاهر=ع، كامن=ك، ثغرة إجراء=ث، ملاحظة=م) |
| 1 | التاريخ | `YYYY-MM-DD` أو `—` للصفوف الموروثة |
| 2 | المحور | `system` · `data` · `process` · `print` · `language` · `security` |
| 3 | العَرَض | ما ظهر فعليًا |
| 4 | السبب الجذري | البنية التي أنتجت الخلل |
| 5 | الإصلاح | ما نُفِّذ؛ يجب أن يحمل `منفَّذ` أو `جزئي` أو `لم يبدأ` |
| 6 | الحاجز | قاعدة المنع + دليل النتيجة |
| 7 | الحالة الأصلية | النص الوارد؛ لا يُبنى عليه حكم |
| 8 | قاعدة الإصلاح | `منفَّذ` \| `قيد التنفيذ` \| `لم يبدأ` |
| 9 | قاعدة التحقق | `تحقق تشغيلي ناجح` \| `تحقق أولي` \| `غير متحقق` |
| 10 | قاعدة الحاجز | `فعّال` \| `مطبَّق` \| `غير موثَّق` |
| 11 | الحالة المشتقة | `مغلق` \| `مفتوح` \| `بانتظار التحقق` \| `موروث غير مثبت` |

المحرّك يقرأ النص الحر من الأعمدة 1–7، ثم يشتق الأعمدة 8–11. صف ذو عدد أعمدة غير 12 = منع.

## 2) اشتقاق الحالة

الحالة لا تُعلن من خانة النص؛ تُشتق من الإصلاح والتحقق والحاجز والتاريخ:

```text
منفَّذ + (مطبَّق|فعّال) + تحقق تشغيلي ناجح  →  مغلق
مفتوح|لم يُصلح|بانتظار قرار                 →  مفتوح
التاريخ = —                                  →  موروث غير مثبت
غير ذلك                                      →  بانتظار التحقق
```

الدليل يُبنى من **الإصلاح والحاجز فقط**، وليس من «الحالة الأصلية». صف نصّه «مغلق» ولا يستوفي الاشتقاق يُخفَّض آليًا.

## 3) دليل النتيجة والتشغيل الحي

لا يُقبل الدليل إلا إذا احتوى نتيجة قابلة لإعادة التشغيل، مثل:

```text
خرج 0 | exit 0 | رمز 2 | نجح N · فشل 0 | N/N | مطابق تمامًا | بصمة <ست خانات فأكثر>
```

الصيغة المعيارية للدليل الحي:

```text
تحقق حي <DATE>: <الأمر> → خرج <N> · <علامة>
```

يُوضع الدليل أول خانة الإصلاح أو الحاجز بلا قصّ؛ لا يكفي «مُصلح» أو «تم» أو «يعمل». لكل صف موروث أو مغلق قديم يجب تشغيل البوابة/الأداة المسماة في نصه الآن، وتسجيل الأمر ومخرجِه ورمز خروجه.

## 4) الفشل المغلق

- انهيار المدقق، أو دليل فارغ، أو معرّف غير معروف، أو حالة غير معروفة = منع.
- الرمز `70` انهيار مدقق ويُعامل منعًا حتى بلا نص.
- صف غير مغلق يحتاج استثناءً صريحًا؛ الاستثناء لا يمنح الإغلاق.
- الاستثناء الصالح يحمل: `fault_id` و`owner` و`reason` و`expiry`/`expires_at` و`evidence`، ولا يُقبل بلا مهلة.
- الاستثناء المنتهي أو المعرّف غير الموجود في السجل = منع.

## 5) مصفوفة التتبع

لكل صف سجل مدخل يتتبع: `fault_id · lesson_id · fix_applied · verify_ok · barrier_active · state · run_evidence`.

- يطبّع `lesson_id` قبل المقارنة: `ك-09` يساوي `ك-9`، وتُقارن القاعدة قبل اللاحقة (`ك-122/ب` → `ك-122`).
- `run_evidence` مقتطف يحتوي نتيجته، لا بادئة مقطوعة.
- لكل صف مغلق: درس مطابق، ومعرّف حاجز صالح، ودليل تشغيل يحتوي علامة نتيجة قابلة لإعادة التشغيل.

## 6) الثبات المزدوج ورموز البوابة

تمريرتان متتاليتان بلا كتابة خاصة يجب أن تنتجا الملف نفسه:

```text
ثبات كامل (سجل + تعلم): نعم
دروس مشتقة: 0
```

ظهور درس مشتق في التمريرة الثانية = عطل في المطابقة أو بناء السجل، ويُعامل كمنع حتى يُشخّص ويُثبت.

| الرمز | المعنى |
|---:|---|
| `0` | مجتاز |
| `2` | منع بسبب مخالفة مؤكدة |
| `70` | انهيار مدقق؛ منع مغلق |

## 7) ملكية الحدود

هذا العقد يملك تعريف «هل الصف مغلق؟» ومخطط السجل والحارس والاختبار العدائي والتتبع. أما التقاط العطل، وتصنيفه، وكتابة درس التعلم، وتحويل الاقتراح إلى تشديد، والدفع في فرع وطلب الدمج، فتملكها [مهارة حلقة التعلم الذاتي](../../self-learning-loop-ops/SKILL.md).
