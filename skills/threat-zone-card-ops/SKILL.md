# تشغيل بطاقة مستوى التهديد بالقطاعات

## النطاق والحدود

استخدم هذه المهارة فقط لنموذج القطاعات، وحكم التهديد، واتساق بطاقة الشاشة والطباعة. لا تستبدل بها تشغيل الكتيب أو النشر أو إرسال Telegram؛ أحِل تلك الأعمال إلى `runbook-execution-ops`. لا تعتمدها لإعادة تجميد CSS أو اعتماد PDF؛ أحِل قياسات الطباعة المقفلة إلى `approved-output-change-ops` و`print-freeze-verify-ops`.

طبّق القاعدة الحاكمة: **مصدر واقعة واحد، قطاع واحد، حكم مشتق واحد، بطاقة واحدة**. لا تصلح التناقض بإخفائه على سطح واحد.

## متى تُستدعى

استدعها عند تشغيل أو تعديل بطاقة مستوى التهديد، أو عند إضافة قطاع/تغيير حدوده أو كلماته، أو عند تعارض مستوى البطاقة مع المتن أو `web/meta` أو بطاقة القرار، أو عند قياس البطاقة حيًا على شاشة أو صفحة إصدار. لا تستدعها لمجرد تشغيل الجولة اليومية إذا لم يتغير نموذج التهديد.

## العقد غير القابلة للتفاوض

### القطاعات

ثبّت أربعة قطاعات فقط، وبالأسماء التالية حرفيًا:

1. `Z1` — **مضيق هرمز وخليج عُمان والخليج العربي**. أدخل خليج عُمان فيه.
2. `Z2` — **باب المندب والبحر الأحمر**.
3. `Z3` — **بحر العرب**.
4. `Z4` — **القرن الأفريقي**. أدخل خليج عدن فيه، لا في Z2.

امنع أي كلمة مفتاحية مكررة بين القطاعات. لا تضف قطاعًا خامسًا ولا تستخدم اسمًا بديلًا في المتن أو البطاقة.

### إسناد الواقعة

طبّق الترتيب الآتي لكل واقعة، ولا تختصره بالبحث النصي العشوائي:

1. أسندها إلى أقرب موقع جغرافي مذكور.
2. عند ذكر موقعين، رجّح موقع الحادث على موقع الجهة المُبلِّغة.
3. قدّم اسم المضيق أو الميناء على اسم البحر.
4. عند غياب موقع بحري، ابحث في المتصفح عما يثبت أنها الواقعة نفسها؛ إن لم يثبت ذلك، وسمها **غير مكانية** واستثنها من حساب القطاعات.
5. عند تزاحم الكلمات، رجّح الكلمة الأطول؛ طبّق ذلك خصوصًا على «خليج عدن» → `Z4`.

اجعل لكل واقعة قطاعًا واحدًا فقط أو `null` مع `nonspatial=true`. لا تنسب واقعة إلى قطاعين، ولا تجعل موقع الجهة المُبلِّغة يطغى على موقع الحادث.

### الأهلية والعدّ

احتسب ما يصيب سفينة أو يمسّ ملاحتها: هجوم، استهداف، ألغام، اختفاء/اختطاف، حريق، غرق، إعاقة أو تعطيل ملاحي، ونشاط مشبوه موجّه لسفينة. احتسب الحريق غير المفسّر لأنه ضرر فعلي. طابق القائمة التفصيلية في `zone-registry.json` ولا تضف نوعًا حرًا.

استبعد الزيارات، البيانات السياسية، الخطط، التنظيمات، النشرات العامة، والتحذير بلا حادثة مثبتة. لا تعدّ الإشارة أو التقرير؛ ادمج تقارير الواقعة الواحدة في `incident_group` وعدّ الحادثة مرة واحدة. اذكر الادعاء غير المؤكد في المتن، لكن لا ترفعه إلى رتبة مؤكدة حتى يوجد بلاغ رسمي أو مصدران مستقلان. أبقِ الادعاء الأحادي ضمن الحد المتاح في السلم، ولا تجعله سببًا لرتبة مرتفعة.

### الحكم ومصدره الواحد

استخرج مستوى القطاع من الوقائع المصنفة، واجعل المستوى العام أعلى رتبة قطاع مع تسمية القطاع الأعلى. اشتق `threat_level` و`decision_card.risk` من الحكم نفسه؛ لا تكتب قيمة مستقلة في الواجهة أو البطاقة. يجب أن تتطابق القيم في:

- `web/zones/<date>.json` (`overall.level`، وكل `zones[].level`).
- `web/meta/<date>.json` (`threat_level`، `threat_zone_levels`، `threat_zones.overall`، `decision_card.risk`).
- المتن: «المستوى العام: …» و«المستوى في <اسم القطاع>: …».
- بطاقة القطاعات والترويسة.

امنع أي لفظ مستوى خارج السلم الخمسي. اربط كل مستوى بلونه المميز من `threat-scale.json`؛ لا تسمح بلون مشترك أو fallback يخفي مستوى غير معروف.

### العرض

اعرض أربعة صفوف، صفًا لكل قطاع، ولا تعرض وسم «= بلا تغير». استخدم «خلال 24 ساعة السابقة» بدل الفترة الرقمية. أظهر أساس التقدير في الشاشة والطباعة عبر `<details open>`؛ افحصه تحت وسيط `print` لا من HTML الخام فقط. اجعل أهداف اللمس لا تقل عن 44px على الجوال. اجعل بطاقة القرار تحيل إلى الترويسة ولا تكرر المستوى العام. امنع تسرب نص `<style>` إلى سطح الطباعة.

## سير العمل المرتب

1. اقرأ العقود الستة أعلاه، وحدد التاريخ وملفات `web/zones`, `web/meta`, والمتن المقابل.
2. افحص التداخل والأسماء والألوان من السجلات الحاكمة قبل التصنيف.
3. شغّل الاختبار الذاتي للمصنف:
   ```bash
   python3 /home/ubuntu/brain-marine-news/tools/classify_zones.py --selftest
   ```
4. بعد تحديث دفتر اليوم أو الأحكام المحوكمة، أعد بناء المصدر المشتق فقط عبر المصنف:
   ```bash
   python3 /home/ubuntu/brain-marine-news/tools/classify_zones.py \
     --date YYYY-MM-DD --write
   ```
   لا تعدّل `web/meta` يدويًا بعد ذلك؛ اترك المصنف يشتق `decision_card.risk` والحقول التابعة.
5. راجع ملف القطاعات: تأكد من أربعة صفوف، `incident_group` بلا تكرار عدّي، أساس غير فارغ لكل قطاع، و`overall.level` مساويًا لأعلى `rank`.
6. راجع المتن والترويسة مقابل المصدر المشتق. صحّح الصياغة المصدرية لا بطاقة سطح واحد.
7. شغّل بوابة الاتساق:
   ```bash
   python3 /home/ubuntu/brain-marine-news/validators/check_threat_consistency.py \
     --date YYYY-MM-DD --brain /home/ubuntu/brain-marine-news
   ```
   أوقف الجولة عند أي رمز غير 0، واقرأ المخرج الحرفي قبل أي تعديل.
8. افتح الصفحة المنشورة أو المحلية وشغّل سكربت القياس المرفق:
   ```bash
   python3 /home/ubuntu/skills/threat-zone-card-ops/scripts/measure_card.py \
     --url https://<host>/reports/YYYY-MM-DD.html
   ```
   استخدم `--file /path/to/report.html` للاختبار المحلي. لا تعتبر رمز 0 كافيًا إذا خالف المخرج أي عقدة.
9. عند تغيير PDF أو CSS المقفل، توقف وأحِل القياس والاعتماد إلى مهارة الطباعة المعتمدة؛ لا تُدخل أوامرها في هذه المهارة.
10. احتفظ بالأمر والمخرج ورمز الخروج لكل فحص في دليل الجولة، ولا تعلن الإغلاق بلا دليل حي.

## قياس السكربت المرفق

شغّل `scripts/measure_card.py` بعد قراءة `--help` إذا اختلفت الصفحة عن بنية `threat_card.py`. يسجل السكربت: `rows`، `min_height_px`، `mobile_min_height_px`، `excess_px`، `print_basis`، `overall_level`، `top_zone_level`، و`overall_matches_top`. يفشل برمز غير صفري عند صفوف غير أربعة، ارتفاع أقل من 44px، فائض أفقي، غياب أساس الطباعة، مستوى غير معتمد، أو اختلاف العام عن أعلى قطاع. يقيس البطاقة المرئية وحدها حتى لا يخلط نسخة `tz-print` المخفية بنسخة `tz-screen`.

## أخطاء وقعت فعلًا اليوم وحواجزها

| العطل | الحاجز الإلزامي |
|---|---|
| تداخل كلمة أو إسناد الواقعة إلى قطاعين | افحص الكلمات المكررة و`--selftest` ثم بوابة الاتساق قبل العرض |
| احتساب الإشارات بدل الحوادث | ادمج `incident_group`، وافحص عدّاد `qualifying` لا عدد التقارير |
| مستوى عام لا يساوي أعلى قطاع | اشتق `overall` من `zones[].rank`، ثم شغّل فحص (2) |
| وسم «= بلا تغير» | فتّش HTML والنص المرئي قبل القياس؛ استخدم `last_change`/«استمراري» فقط عند عقد الحمل |
| فترة رقمية في الترويسة | استخدم النص المغلق «خلال 24 ساعة السابقة» وشغّل فحص (9) |
| وسم `<style>` يظهر في الطباعة | افصل CSS عن المحتوى أو امنع قاعدة الطباعة العامة من مطابقة `<style>`، ثم افحص `print_basis` ومخرج PDF عبر مهارة الطباعة |

## التعلم الذاتي وإغلاق الأعطال

عند اكتشاف أي عطل جديد، أوقف التسليم وسجله في `audit/سجل-الأعطال-والثغرات.md` عبر `fault-closure-ops`. اجعل كل صف بهذه الأعمدة الاثني عشر حرفيًا:

`المعرّف · التاريخ · المحور · العَرَض · السبب الجذري · الإصلاح · الحاجز · الحالة الأصلية · قاعدة الإصلاح · قاعدة التحقق · قاعدة الحاجز · الحالة المشتقة`

اربط صف العطل بمعرّف الدرس في `memory/learning-log.jsonl` وبمعرّف مصفوفة التتبع المعتمدة. سجّل أمر الإثبات ومخرجه ورمز خروجه، لا عبارة «تم الإصلاح». شغّل حارس الإغلاق والاختبار العدائي، مع إحالة التنفيذ إلى المهارة المالكة:

```bash
python3 /home/ubuntu/skills/fault-closure-ops/scripts/check_closure.py \
  --brain /home/ubuntu/brain-marine-news
python3 /home/ubuntu/skills/fault-closure-ops/scripts/test_closure_gate.py
```

لا تقل «مغلق» إلا إذا اشتق الحارس الحالة من إصلاح + تحقق حي + حاجز فعلي. إذا تكرر صنف الخطأ، حدّث هذه المهارة نفسها بإضافة العَرَض والحاجز والاختبار السلبي، ثم أعد تشغيل `quick_validate.py` وسكربت القياس والبوابة. لا تلمس سجل `audit/` أثناء إنشاء المهارة أو اختبارها إذا كان وكيل الإغلاق مخولًا به.

## معيار التسليم

سلّم مسار `SKILL.md`، ومخرج `quick_validate.py` الحرفي، وأمر سكربت القياس ومخرجه ورمز خروجه. اذكر أي سطح أو فحص لم يُنفّذ. لا تنشئ `.skill` على السحابة ما لم يفشل التحقق بسبب الحزم ويطلب ذلك صراحة.
