# إصلاح التوقف المغلق في الكتيب والاستئناف من الخطوة نفسها

استخدم هذا المسار عندما يعيد محرّك الكتيب رمز الخروج `2` (فشل مغلق مقصود) أو `1` (فشل اختبار) عند خطوة ما. القاعدة الأولى: **لا تخفّض حارسًا ليمرّ، ولا تفبرك بيانات لتُسكت حارسًا.** الفشل المغلق رسالة صحيحة عن تعارض حقيقي، ومهمتك إصلاح مصدر التعارض.

## الحدود والإحالات

- املك هنا **تصنيف المنع، اختيار الإصلاح الصحيح، إعادة القياس، والاستئناف من الخطوة نفسها**.
- أحِل استعادة الأصول الحاكمة الموسّعة (مقارنة كل المهارات والبصمات وشواهد مفقودة كثيرة) إلى `governing-assets-recovery-ops`.
- أحِل مخطط الأعطال (12 عمودًا) والدرس ومصفوفة التتبع والثبات المزدوج إلى `fault-closure-ops`.
- أحِل معنى أكواد الكتيب وتسلسله إلى `runbook-execution-ops`، وقيادة جولة متعددة التوقفات إلى `runbook-completion-closure-ops`.
- لا تعِد تعريف هذه الآليات؛ سجّل الأمر والمخرج والرمز الفعلي.

## المسار الإلزامي

1. **اقرأ الحكم الحرفي أولًا.** لا تفسّر من الذاكرة:
   ```bash
   python3 tools/runbook.py run --date <DATE> > /tmp/rb-<DATE>.log 2>&1; echo "RUNBOOK_RC=$?"
   tail -25 /tmp/rb-<DATE>.log
   ```
   خذ اسم الخطوة من `✘ توقف عند <STEP>: رمز الخروج <N>`، ثم اقرأ سجلها الكامل `logs/runbook/<DATE>/<STEP>.log` وأمرها من `runbook/runbook.json`. افحص `pgrep -af 'runbook.py run'` قبل أي تشغيل؛ لا تشغّل تشغيلين متوازيين.

2. **صنّف مصدر المنع قبل أي تعديل.** شغّل الأداة المرفقة:
   ```bash
   python3 scripts/diagnose_closed_fail.py --brain /home/ubuntu/brain-marine-news --date <DATE>
   ```
   الأصناف وإصلاحها:

   | الصنف | العَرَض الحرفي | الإصلاح الصحيح |
   |---|---|---|
   | تعارض سجل بيانات مع الدفتر | «يوم موسوم no_material وله مادة أيضًا» أو أي يوم في سجل استثناءات وله ملف يومي بمادة | عدّل **سجل الاستثناءات** ليطابق الواقع الموثّق، ولا تحذف وقائع رسمية. أعد تشغيل الحارس وحده قبل الكتيب |
   | نقص في أرضية الأصول الحاكمة | «أصل حاكم مفقود أو خارج النطاق» أو «نقص في أصل معتمد» | استعد الأصل المفقود من المرآة ثم من تاريخ Git؛ ولا تُدرج المستعاد في قرار القبول |
   | أرضية متقادمة لتعديل مقصود | نقص بايت/سطر في ملف عُدّل بقرار موثّق والمزامنة سجّلته | قرار صريح بالسبب عبر `--accept`/`--decisions` مع `--reason` يذكر الملف والدليل، ثم `--update` |
   | عطل حقيقي في أداة أو اختبار | استثناء، مسار خاطئ، أو فشل اختبار في `tests/` | أصلح الشيفرة أو الاختبار، وأضف اختبار انحدار، واربطه بالمانيفست |

3. **استعد قبل أن تقبل.** للملفات المفقودة أو المنقوصة: المرآة أولًا، ثم تاريخ Git:
   ```bash
   R=/home/ubuntu/mda-marine-system
   cp "$R/<relative-path>" "/home/ubuntu/<target-path>"
   git -C "$R" log --format='%h %ad %s' --date=short -6 -- <repo-path>
   git -C "$R" cat-file -s "$(git -C "$R" rev-parse <commit>:<repo-path>)"
   ```
   اختر النسخة الأكبر الموثّقة في السجل، وتحقّق أنها ليست نسخة قديمة تُلغي تعديلًا أحدث.

4. **لا تقبل نقصًا بلا سبب مكتوب.** لقرار الأرضية استخدم قرارات جماعية في ملف؛ مسارات المهارات مطلقة والمسارات داخل الجذر نسبية:
   ```bash
   printf '%s\n' '<relative-path>' '/home/ubuntu/skills/<skill>/<file>' > /tmp/asset-decisions.txt
   python3 validators/check_asset_floor.py --decisions /tmp/asset-decisions.txt --reason "<سبب صريح + دليل المزامنة>"
   python3 validators/check_asset_floor.py --update
   ```
   شرط القبول: `النتيجة: سليم`. القرار على مسار غير معروف في الأرضية فشل مغلق، والسبب يجب أن يذكر المقارنة قبل/بعد ودليل المزامنة.

5. **أعد القياس على الحارس وحده، ثم على الكتيب.** شغّل أمر الحارس مباشرة أولًا (سريع، بلا بناء)، ثم أعد الكتيب:
   ```bash
   python3 validators/<guard>.py --date <DATE>; echo "rc=$?"
   python3 tools/runbook.py run --date <DATE>
   ```
   الخطوات المكتملة لا تُعاد؛ المحرّك يستأنف من الخطوة الفاشلة. لا تستخدم `--redo` إلا إذا بَطل ناتج خطوة مكتملة فعلًا بسبب إصلاحك.

6. **وثّق العطل والدرس فورًا.** أضف صفًا في `audit/سجل-الأعطال-والثغرات.md` بالأعمدة الـ12 (`المعرّف · التاريخ · المحور · العَرَض · السبب الجذري · الإصلاح · التشديد والحالة · الحالة الأصلية · حالة الإصلاح · حالة التحقق · حالة الحاجز · الحالة التشغيلية`)، ومدخلًا مقابلًا في `memory/learning-log.jsonl`، ثم:
   ```bash
   python3 tools/closure_round.py --apply
   python3 validators/check_closure.py
   ```
   لا تعلن الإغلاق بلا تشغيل حي اليوم.

7. **حصّن منع التكرار.** أضف اختبارًا سالبًا يثبت أن الحارس يفشل مغلقًا عند التعارض نفسه، واختبارًا موجبًا يثبت أنه يمرّ بعد الإصلاح. إن أفلت العطل سابقًا من الحارس فشدّده، ولا تُخفّف القاعدة لتمريره.

## القواعد الحاكمة

- رمز `2` يعني توقفًا مقصودًا: أوقف النشر وTelegram والنسخة الاحتياطية حتى يُصلح المصدر ويعاد القياس.
- لا نشر ولا إرسال ولا نسخة احتياطية من خارج خطوة في المانيفست.
- القرار الصريح المسجَّل بالسبب هو الطريق الوحيد لقبول نقص؛ القبول الصامت ممنوع.
- سجل الاستثناءات يتبع الواقع الموثّق لا العكس: لا تحذف واقعة رسمية لتوافق سجلًا.
- لا تعدّل بيانات تاريخية لتُسكت حارسًا؛ عدّل السجل الذي صار خطأً.
- إن كان الحارس نفسه معطوبًا، أصلح الحارس وأضف اختبارًا؛ لا تُلغِ الفحص.

## الأداة المرفقة

`scripts/diagnose_closed_fail.py` قراءة فقط: يحدد الخطوة الفاشلة ورمز الخروج من سجل التشغيل، ويطبع ذيل سجل الخطوة، ويصنّف المنع إلى أحد الأصناف الأربعة، ويطبع الإصلاح المقترح. يعيد `0` عند وجود خطوة فاشلة مصنّفة، و`1` عند غياب تشغيل فاشل، و`2` عند وسيط غير صالح. شغّل `--help` أولًا وتأكد أنه يخرج بـ`0`.
