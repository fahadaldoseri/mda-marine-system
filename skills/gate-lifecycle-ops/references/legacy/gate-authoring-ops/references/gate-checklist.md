# قائمة تحقق اعتماد بوابة فحص

استخدم هذه القائمة قبل اعتماد أي بوابة جديدة أو إصلاح بوابة قديمة. لا تُعلِن المطابقة قبل امتلاك دليل لكل بند.

## العقد والقياس

- [ ] اكتب في رأس الملف تعليقًا يشرح بوضوح ما تمنعه البوابة.
- [ ] ثبّت واجهة `argparse` للخيارات المطلوبة: `--date` و`--brain` و`--site` و`--pdf` و`--json`، أو وثّق استثناءً مبررًا.
- [ ] اجعل كل مدخل مفقود أو فارغ أو غير قابل للقراءة أو غير قابل للقياس **منعًا**.
- [ ] افصل الحكم في دالة `violations()` قابلة للاستيراد؛ لا تجعل الاختبار ينسخ منطق البوابة.
- [ ] اطبع السبب الحرفي لكل مخالفة، لا «فشل» عامًا ولا تحذيرًا يوهم بالنجاح.
- [ ] ثبّت العقد: `0 = مطابق` و`2 = منع`. لا تستخدم نجاحًا صامتًا عند الاستثناء.

## الاختبار العدائي

- [ ] اختبر مدخلًا سليمًا يخرج `0`.
- [ ] اختبر مخالفة المجال التي تمنعها البوابة وتخرج `2`.
- [ ] اختبر مدخلًا مفقودًا أو غير قابل للقياس؛ يجب أن يمنع فشلًا مغلقًا ويطبع السبب.
- [ ] شغّل الاختبار من استيراد دالة البوابة، لا من نسخة منطقية مكررة.
- [ ] اطبع نتيجة قابلة للإثبات: `نجح N · فشل 0`.
- [ ] أضف كل حالة فشل جديدة إلى الاختبار، وأثبت أنها كانت ستفشل قبل التشديد.

## التشغيل والربط

- [ ] شغّل البوابة على مخرج حقيقي مبني حاليًا، والتقط الأمر والمخرج ورمز الخروج.
- [ ] اربطها في `tests/run_checks.sh` عبر دالة العداد الموجودة (`t` أو ما يعادلها)، لا عبر `|| true` أو مسار يتجاهل الرمز.
- [ ] شغّل `scripts/wire_into_runner.py` بوضع dry-run، راجع الفرق، ثم طبّق بـ`--apply`.
- [ ] أعد تشغيل أداة الربط وتأكد أن السطر لا يتكرر.
- [ ] شغّل المشغّل بعد الربط وتحقق أن عدّاد `FAIL` يتغير عند منع متعمد.

## التعلم والإغلاق

- [ ] عند نتيجة كاذبة، سجّل العطل والسبب الجذري والإصلاح والحاجز وفق `fault-closure-ops`.
- [ ] أضف درسًا JSONL إلى `memory/learning-log.jsonl` بالحقول: `ts` و`entry_kind` و`cls` و`status` و`symptom` و`cause` و`fix` و`barrier`.
- [ ] اربط الدرس بحالة اختبار سلبية جديدة تمنع عودة العطل.
- [ ] أعد القياس الحي، ثم أعد الفحص مرتين عند طلب قواعد الثبات في `fault-closure-ops`.
- [ ] إذا كان الفحص يخص موضع قسم أو سطح تقرير، طبّق `report-surface-policy-ops`؛ وإذا كان لغويًا، طبّق `vocabulary-guard-ops`.
- [ ] شغّل `quick_validate.py` على المهارة بعد اكتمال الملفات.

**قاعدة القرار:** إذا غاب أي دليل أعلاه، فالحالة `منع` وليست «مقبولة مع ملاحظة».
