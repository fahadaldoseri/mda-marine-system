# القياس الحي المحكم لأدوات سطر الأوامر

## المبدأ ومتى تُستدعى

قِس السلوك الفعلي داخل حاوية محكمة بدل استنتاج السلامة من AST أو رمز الخروج وحده. استدعِ هذه المهارة عند وجود أداة تكتب أو تتصل أو تنشر ويجب قياسها بلا مخاطرة، أو عند الشك في كتابة ضمنية، أو قبل إدخال أداة في مانيفست/بوابة، أو عند الحاجة إلى دليل قابل لإعادة التشغيل.

**الإحالات الإلزامية:** استخدم `argv-tools-safe-probe-ops` للتصنيف الساكن أولًا، و`side-effects-interface-audit-ops` لملكية الآثار الجانبية، و`tool-contract-check-ops` لعقد الوسائط والمخرج والرموز؛ لا تكرر ملكيتها هنا. إذا كان السياق يطلب المصنف الحاكم للمشروع، أحِل إلى `python3 tools/classify_argv_tools.py` ضمن `argv-tools-safe-probe-ops` ولا تنشئ مصنفًا بديلًا.

## المسار الإلزامي

نفّذ الخطوات بالترتيب، وسجّل الأمر والمخرج الحرفي ورمز الخروج:

1. **صنّف ساكنًا أولًا.** أحِل إلى `argv-tools-safe-probe-ops`، ولا تعتبر التصنيف الساكن قياسًا حيًا.
2. **جهّز العزل.** أنشئ نسخة عمل قابلة للكتابة خارج المشروع، تحت `/tmp`، واربط شجرة المشروع الأصلية للقراءة فقط. استخدم `bwrap --unshare-all --die-with-parent --unshare-net` مع جذر `--ro-bind / /` و`--tmpfs /tmp` و`--proc /proc` و`--dev /dev`، واربط نسخة العمل وحدها كمسار العمل.
3. **شغّل ثلاثة أوضاع على الأقل لكل أداة.** نفّذ `--help`، ثم وسيطًا غير معروف مثل `--__hermetic_unknown__`، ثم التشغيل الآمن الموثق. لا تمرر الأمر عبر shell غير لازم، ولا تُشغّل أداة حقيقية من شجرة المشروع.
4. **سجّل لكل تشغيل.** احفظ رمز الخروج، المدة، المخرج الحرفي، الملفات المكتوبة داخل نسخة العمل، `connect`، `execve`، `net_packets`، وبصمات SHA-256 قبل/بعد. التقط trace عبر `strace -f -qq -e trace=%file,%network,execve` أو الصيغة الصريحة عند رفض الاختصار.
5. **احكم صراحة.** اكتب `مقيس` إذا اكتمل القياس، أو `غير قابل للقياس داخل الحاجز` مع السبب إذا غاب عداد الشبكة/trace/البصمات أو تعذر تشغيل الحاجز. لا تستبدل الحكم باستنتاج ساكن.
6. **أصلح العقد فقط عند الحاجة.** اجعل `--help` يخرج `0` قبل الأثر، والمجهول يخرج `2` بلا تنفيذ، وضع الكتابة خلف خيار صريح. لا تغيّر وظيفة الأداة ولا تُخفي عطلًا حقيقيًا.
7. **أعد القياس بعد كل إصلاح.** أعد الأوضاع الثلاثة واللقطات، ثم أعد الجولة مرة ثانية لإثبات الثبات. لا تعلن الإصلاح قبل تطابق العقد والبصمات.
8. **أخرج جدولًا لكل أداة.** استخدم الأعمدة: الأداة، الوضع، رمز الخروج، المدة، الكتابة داخل النسخة، `connect`، `execve`، `net_packets`، التغير خارج العزل، حالة القياس، والحكم.

## معايير الحكم المقفلة

- اجعل `net_packets = 0` شرطًا لازمًا؛ سجّل محاولات `connect` حتى لو فشلت.
- اعتبر أي تغيّر مثبت خارج العزل فشلًا مغلقًا للجولة، وأوقف التسليم.
- اعتبر `ENETUNREACH` داخل الحاجز فشل شبكة مقصودًا وقياسًا ناجحًا للعزل، لا عطلًا في الأداة.
- قِس المهلة ولا تهملها؛ سجّل `124` عند انتهاء `timeout`.
- لا تصف وظيفة معطلة داخل الحاجز بأنها «ناجحة»؛ افصل «القياس مكتمل» عن «وظيفة الأداة نجحت».
- لا تعتبر ملفًا كُتب داخل نسخة العمل ضررًا؛ طابقه مع بصمة المشروع الأصلية، وسجّل المسار.

## عقد السكربت المرفق

استخدم `scripts/live_probe_batch.py` مع قائمة مسارات أدوات وملف JSON للإعداد:

```bash
python3 scripts/live_probe_batch.py --config /tmp/probe.json tool_a.py tool_b.py
```

يجب أن يحدد الإعداد `project_root`، ويمكنه تحديد `runner` (مثل `["python3"]`)، و`timeout_seconds`، و`output_dir`، و`work_parent`، و`modes.safe`. ينشئ السكربت نسخة عمل جديدة لكل وضع، يقرأ المشروع أصليًا فقط، يطبع جدولًا، ويكتب JSON مستقلًا لكل أداة. يعيد `0` عند اكتمال القياس مع `net_packets=0` وعدم تغيّر المسارات المراقبة، ورمزًا غير صفري عند تغيّر خارج العزل، أو `net_packets > 0`، أو غياب أي قياس. اجعل `--help` يخرج `0` والمُعطى غير المعروف `2`.

لا تفترض أن `systemd-run` متاح: في القياس المرجعي رُفض إنشاء scope بـ`Access denied`، فاستُخدم `ulimit + timeout` بدل cgroup. لا تدّعِ حدود موارد لم تُقَس، وتذكّر أن `inotify` لا يعطي اسم العملية.

## أخطاء يجب إيقافها

| الخطأ | التصحيح |
|---|---|
| تشغيل أداة تكتب داخل المشروع «للتجربة» | انسخها إلى `/tmp` واربط المشروع الأصلي للقراءة فقط |
| تفسير `ENETUNREACH` كعطل | افحص `connect` و`net_packets`؛ صفر الحزم يثبت العزل |
| الاعتماد على `systemd-run` بلا تحقق | سجّل الرفض واستخدم حدًا مقيسًا بـ`timeout`/`ulimit` |
| الادعاء بحدود cgroup مع عدم وجود scope | اذكر أن حدود cgroup غير مثبتة |
| الخلط بين نجاح العقد ونجاح الوظيفة | سجّل كلًا من عقد الخروج وحالة الوظيفة |
| تجاهل المهلة أو trace الناقص | احكم «غير قابل للقياس» وسجّل السبب |

## التعلم الذاتي والإغلاق

عند كل عطل أو سلوك مفاجئ، أضف صفًا في سجل الأعطال بصيغة الأعمدة الاثني عشر المعتمدة، وأضف درسًا إلى سجل التعلم، واربط الدليل بمصفوفة التتبع، ثم شغّل حارس الإغلاق المالك حتى يثبت السبب الجذري والإصلاح والحاجز. حدّث هذه المهارة عند تكرار النمط، وأعد القياس السلبي لمنع عودته؛ لا تكتفِ بتغيير النثر. هكذا تتعلم المهارة من نفسها: **قياس حي → عطل موثق → سبب جذري → حاجز آلي → إعادة قياس → درس وتحديث عند التكرار**.

## دليل اليوم المرجعي

احفظ في التقرير أن تجربة القراءة أعادت `0`، ومحاولة الكتابة أعادت `WRITE_FAILED:OSError` ورمز `7` دون إنشاء الهدف، ومحاولة الشبكة أعادت `ENETUNREACH` ورمز `1`، والمهلة أعادت `124`؛ بقي `net_packets = 0` في التجارب الأربع، ولم يتغير ملف خارج العزل، ونجحت اختبارات `pytest` الستة. هذه وقائع معايرة للمسار وليست بديلًا عن تشغيل الأداة الحالية.
