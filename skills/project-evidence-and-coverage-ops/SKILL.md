# أدلة المشروع وتغطية التشغيل

## الغرض
اجعل كل ادعاء تشغيلي قابلًا لإعادة التشغيل: مدخل معلوم، أمر كامل، مخرج محفوظ، ورمز خروج. لا تعتبر وجود ملف أو وعدًا في مانيفست دليلًا على أن العملية استُدعيت.

## متى تستخدم
- عند إعداد جولة جديدة قبل التخطيط أو قبل إعلان الجاهزية.
- عند ظهور فرق بين المهارات المعلنة في السجل والمهارات التي يستدعيها المانيفست.
- عند الحاجة إلى ربط مصدر ← بيانات ← مولّد ← سطح ← بوابة.
- عند طلب قياس ميزانية أداء أو توحيد ملاحظات المالك والخطة.

## الحدود
هذه المهارة لا تؤلف البوابات، ولا تغلق الأعطال، ولا تنشر الموقع؛ استخدم `gate-lifecycle-ops` للتأليف، و`fault-closure-and-learning-ops` للإغلاق، و`parity-and-publish-ops` للنشر.

## القاعدة الحاكمة
لا تكتب رقمًا مشتقًا يدويًا. احفظ الأمر الكامل، والوقت المنقضي، ورمز الخروج، ومسار JSON الخام، وبصمة المخرج عند توفرها. غياب الدليل = «وعْد غير مقيس»، لا نجاح.

## الأقسام التشغيلية الخمسة

### 1) ميزانية الأداء بالأمر الكامل
**المدخل:** الأمر الكامل كما سيُشغّل، التاريخ، الجذر، ميزانية كل مؤشر، ووجهة `perf-budget.json`.

**الخطوات:** شغّل الأمر كما هو من الجذر الصحيح؛ قِس `elapsed_seconds` ووقت CPU/الذاكرة إن كانت الأداة توفرهما؛ احفظ الأمر والبيئة المختصرة ورمز الخروج؛ قارن كل مؤشر بميزانيته دون تقريب يخفي التجاوز.

**المخرج:** `audit/measurements/perf-budget-<date>.json` يتضمن `command`, `exit_code`, `elapsed_seconds`, `budget_seconds`, `status`, و`sha256` للمخرج المقاس.

**الدليل المقيس المطلوب:** مثال الجولة الأخيرة: سجل الأداء يثبت `elapsed_seconds` مع ملف `perf-budget.json`، وليس عبارة «سريع». إن لم يوجد ملف JSON صالح أو لم يظهر الأمر كاملًا فاكتب «وعْد غير مقيس».

**الحاجز عند الفشل:** رمز غير صفري، ملف مفقود/فارغ، أو تجاوز الميزانية يمنع الجولة ويُسجّل كعطل أداء؛ لا تُرفع الميزانية لتجاوز الفشل دون قرار مالك.

### 2) مرجع آلية العمل من ملاحظات المالك
**المدخل:** ملاحظات المالك المؤرخة، القرار أو الخلاف، الملفات والأسطح المتأثرة، والنسخة الحالية من الخطة.

**الخطوات:** طبّع كل ملاحظة إلى مطلب قابل للفحص؛ اربطها بمالك ومخرج وموعد؛ افصل القرار المحسوم عن السؤال المفتوح؛ اجمعها في مرجع واحد ولا تنسخها إلى برومت منفصل بلا معرّف.

**المخرج:** مرجع آلية عمل يضم `note_id`, `decision`, `owner`, `surface`, `acceptance_check`, `status`, و`evidence_path`، مع قائمة قرارات معلّقة.

**الدليل المقيس المطلوب:** مثال الجولة الأخيرة: كل بند قابل للتتبع إلى `gate-audit-*.json` أو مخرج آخر، ويظهر عدد البنود المحسومة والمفتوحة؛ لا يكفي وجود ملف ملاحظات بلا روابط أدلة.

**الحاجز عند الفشل:** ملاحظة بلا مالك أو معيار قبول أو حالة تمنع اعتماد المرجع؛ لا تُحوّل رغبة لغوية إلى قاعدة بوابة دون معيار قابل للقياس.

### 3) مصفوفة التتبع ثنائي الاتجاه
**المدخل:** سجل المصادر، سجلات البيانات، ملفات المولدات، الأسطح المقروءة، ومعرّفات البوابات.

**الخطوات:** أنشئ صفًا لكل ادعاء/رقم؛ اربطه في الاتجاه الأمامي مصدر → بيانات → مولّد → سطح → بوابة، وفي الاتجاه العكسي بوابة/سطح → مولّد → بيانات → مصدر؛ افحص الفقد والتكرار والروابط الميتة.

**المخرج:** `traceability-matrix.json` أو CSV ثابت المخطط، مع `claim_id`, `source_id`, `data_path`, `generator`, `surface`, `gate`, `evidence`, و`status`.

**الدليل المقيس المطلوب:** مثال الجولة الأخيرة: `gate-audit-*.json` يذكر عدد الصفوف، وعدد الروابط المكتملة، وعدد الفاقد؛ أي رقم بلا `source_id` أو `gate` يصنّف «غير مثبت».

**الحاجز عند الفشل:** صف بلا طرف أو أكثر، أو رابط إلى ملف غير موجود، أو ادعاء يظهر على سطح ولا يعود إلى المصدر، يمنع التسليم برمز غير صفري.

### 4) جرد جاهزية البيئة قبل التخطيط
**المدخل:** الجذور الفعلية، الأدوات والإصدارات، الصلاحيات، الملفات الحاكمة، الاتصال المطلوب، وحالة الأقفال/العمليات.

**الخطوات:** افحص وجود كل مدخل قبل وضع خطة؛ جرّب `--help` للأدوات المرشحة دون أثر؛ ميّز «موجود» من «قابل للتشغيل»؛ سجّل المفقود والمخاطر والبديل؛ لا تُدخل مسارًا غير متاح في الخطة.

**المخرج:** `environment-readiness.json` يحوي `check`, `command`, `exit_code`, `observed`, `required`, `risk`, و`next_action`.

**الدليل المقيس المطلوب:** مثال الجولة الأخيرة: يربط الجرد بين `approved-skills.json` والأدوات الفعلية، ويعرض رموز فحوص `--help` ومساراتها؛ «البيئة جاهزة» بلا مخرجات = وعْد غير مقيس.

**الحاجز عند الفشل:** مدخل حاكم مفقود، أداة لا تقبل `--help`/المعاملات المتوقعة، أو قفل قائم يمنع التخطيط؛ أوقف التخطيط حتى يصدر قرار أو بديل موثق.

### 5) تغطية المُعلَن مقابل المستدعى
**المدخل:** السجل الحاكم للمهارات، مانيفست التشغيل، المهارات المستدعاة فعليًا، ومسارات الخطوات.

**الخطوات:** اقرأ السجل بصرامة؛ استخرج القوائم آليًا؛ طابق المعلن مع المستدعى في الاتجاهين؛ تحقق من وجود `SKILL.md` صالح لكل اسم؛ سجّل المعلن بلا استدعاء، والمستدعى بلا إعلان، والاسم المكرر أو القديم.

**المخرج:** `gate-audit-<date>.json` يضم `declared`, `invoked`, `missing_declared`, `missing_invoked`, `duplicates`, `exit_code`, و`sha256`.

**الدليل المقيس المطلوب:** مثال الجولة الأخيرة: `approved-skills.json` هو مصدر القائمة المعلنة، و`gate-audit-*.json` يحفظ المقارنة والأعداد؛ لا تُعلن «تغطية كاملة» من عدّ يدوي.

**الحاجز عند الفشل:** سجل مفقود/فارغ/غير صالح، اسم مستدعى غير معلن، أو اسم معلن بلا مسار صالح = فشل مغلق برمز 2.

## حلقة التعلم الذاتي
بعد كل فشل أو إنذار كاذب سجّل: **عطل** (ما ظهر ورمز الخروج) ← **درس** (السبب البنيوي) ← **حاجز** (قاعدة/اختبار يمنع التكرار) ← **اختبار** (أمر موجب وسالب يعيد القياس). مثال: عُدّ اسم معلن بلا استدعاء؛ الدرس أن المقارنة كانت أحادية الاتجاه؛ الحاجز مقارنة الاتجاهين؛ الاختبار يحقن اسمًا في كل طرف ويطلب `gate-audit-*.json` برمز 2. إن لم يُشغّل الاختبار الحقيقي، اكتب «لم أختبره».

## أخطاء شائعة
- استخدام زمن تقريبي بدل `elapsed_seconds`.
- نسخ ملاحظة المالك إلى عدة ملفات بدل مرجع بمعرّف واحد.
- مصفوفة تتبع أحادية الاتجاه.
- اعتبار توفر الأداة جاهزية.
- مطابقة أسماء المهارات دون فحص المسار والمحتوى.

## تسليم سريع
قدّم مسارات JSON، الأوامر الكاملة، رموز الخروج، البصمات، وعدد الفاقد/المكتمل. افصل دائمًا بين «نجح بقياس» و«وعْد غير مقيس».
